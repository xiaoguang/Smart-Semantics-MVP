# 管伊佳数据标准化审阅体验

## 状态与范围

本文件是管伊佳数据标准化审阅体验的当前权威设计。它记录 2026-08-28
已批准的纠偏合同；实现、测试和当前事实文档必须以它为准。外部计划、
带日期的交接记录和冻结 V6 内容不是本文件的替代物。

本轮修复审阅投影、来源差异处理时机、内容卡布局和最终合并文档预览。不得修改 V6、
Pinned Bundle、正式管伊佳 V1、零售 V1/V2、黄金摘要、原始证据或快照；
不得调用 LLM、来源系统、capture、package、freeze 或 V7 生成器。

## 术语

| 用户语言 | 内部概念 | 说明 |
| --- | --- | --- |
| 待确认事项／本来源建议 | Scripted review task | 用户需要保留或采用的本来源建议。 |
| 待确认事项／来源差异 | Formal conflict | 前提已齐全、可以保存正式决定的跨来源问题。 |
| 待确认事项／等待更多来源 | Preliminary comparison | 已看到比较问题，但尚未具备决定前提。 |
| 待补充资料 | `GAP` | 材料不足的逐项业务记录，不阻断来源推进。 |
| 已处理事项 | Saved decision | 已保存、继续可读的建议或来源差异决定。 |

用户界面和阅读版不得显示英文 `GAP`。内部枚举、冻结 JSON、Markdown
源文和复制内容继续保持原样。

“待确认事项”只保留区段标题与计数，不能再包裹共同的黄色外框。“本来源建议”和
“来源差异与比较”是两个视觉独立的同级 Box：前者沿用当前提示色，后者使用现有中性／
蓝色比较样式；没有建议时隐藏第一个 Box。审阅列宽大于 959px 时，两个 Box 内的
内容卡使用恢复自 `main` 的三列内容卡；
959px 及以下为单列。390px、320px 和浏览器真实 200% 缩放时，操作可
换行或占满一行，但页面不得依赖横向滚动。布局选择使用稳定 CSS class，
不使用中文 `aria-label`。

## 三页签职责

### 审阅事项

审阅事项固定包含三个组，且所有跨来源比较与差异都在这里：

1. **待确认事项**：本来源建议、已具备决定条件的来源差异，以及显示为
   “等待更多来源”的前提不足比较项。
2. **待补充资料**：当前来源和跨来源的资料不足项；每项单独成行。
3. **已处理事项**：已保存的本来源建议和来源差异决定。切换来源后仍保留。

当前来源页只从当前精确来源文档第九章规范条目产生逐项“待补充资料”；最终结果预览
才聚合五份来源的全部补充资料。正式来源差异与相关补充资料必须分别保留，并以
“关联：……”互相标注，不得相互吞并。

### 审阅结论

只包含核心业务结论和默认展开的完整对象目录。不得出现来源差异、
本次读取发现或待补充资料。

### 标准化文档

保留同一 revision 的阅读版和 Markdown 源文。阅读版继续使用 V6 的九章、
DDL、源码和展开体验，只把可识别的连续 `GAP n` 投影成逐项“待补充资料”。
Markdown 源文及复制结果逐字保持冻结原文。

## 来源差异与来源主线

跨来源事项按运行级投影，而不是由当前打开文档决定，因此切换到官方资料、
ERP 制度或术语图后未决事项不会消失。顺序固定为：欠款字段、负库存、
状态 9。Semantica 只能追加佐证，不得创建第四项差异。

`introducedConflictIds` 是正式来源差异存在的唯一权威。所有已引入差异必须且只能
出现在“来源差异与比较”的未决卡或“已处理事项”的已保存卡中；
`resolvedConflictIds` 必须与后者逐项相等。候选比较只补充卡片内容和前提状态，
不得过滤正式差异。若冻结候选资料无法构造某个已引入差异的卡片，页面显示带该差异
身份的完整性错误并阻止相关写操作和结果生成，绝不静默隐藏或猜测内容。

| 当前状态 | 页头唯一 Primary | 差异行行为 |
| --- | --- | --- |
| `DOCUMENT_READY` 且有本来源建议 | 核对 N 项建议 | 可见，说明须先完成建议。 |
| 建议已完成，来源尚未审阅 | 完成{来源}审阅 | 第一项已具备前提的差异可由次级入口处理。 |
| 已审阅且仍有待阅来源 | 审阅下一个来源 | 第一项未决差异仍可从行进入。 |
| 全部来源已审阅且仍有差异 | 处理 N 项来源差异 | 第一项可进入。 |
| 差异层已打开 | 保存当前决定 | 隐藏下层来源页头 Primary。 |
| 全部来源和差异完成 | 生成标准化结果 | 没有未决差异动作。 |

同一来源同时存在建议与差异时，差异立即可见；用户必须先保存本来源建议，
随后可在完成来源审阅之前保存第一项已具备前提的差异。保存差异决定不自动
完成来源审阅、不自动开始下一来源，也不改变文档 revision。正式决定一旦保存，
命令层必须拒绝会改写该 revision 的文档修改或助手 Patch 确认。

完成来源审阅后，文档、页签、滚动位置和 revision 仍保留。用户点击
“审阅下一个来源”才会切换；差异层临时覆盖来源文档层，关闭后恢复原位置。

## 运行时兼容性

不新增运行状态、Schema、命令或事件类型。新运行的记录顺序为：

```text
DOCUMENT_GENERATED → CONFLICT_FOUND → [CONFLICT_RESOLVED] → DOCUMENT_REVIEWED
```

历史运行继续支持：

```text
DOCUMENT_GENERATED → DOCUMENT_REVIEWED → CONFLICT_FOUND → CONFLICT_RESOLVED
```

文档审阅与冲突解决必须正交验证。`COMPLETE_SOURCE_DOCUMENT` 在文档就绪时
记录已引入差异，但运行保持 `REVIEWING_DOCUMENT`；
`RESOLVE_SOURCE_CONFLICT` 也接受 `REVIEWING_DOCUMENT + DOCUMENT_READY`，并且
只允许处理整个运行中的第一项未决差异；`MARK_DOCUMENT_REVIEWED` 在所有已引入
差异已解决时进入 `ALIGNED`，否则进入 `CONFLICT_BLOCKED`。

未决差异不阻断开始后续来源，但所有正式决定保存前不得生成结果。`READY_FOR_OUTPUT`
仍是交付物生成的唯一门槛。

## 展示转换边界

`projectReviewSupplementSegments(value)` 是只读展示转换：识别 `GAP：`、
`GAP 1：`、`GAP 2：`、`资料缺口：` 和 `待确认：`，保留业务文字和顺序，输出
独立补充资料行。无法可靠切分时，完整文字保留为一项，绝不丢失内容。它不得
修改 V6、Markdown、SHA 或复制内容。

## 最终合并文档预览

五份来源均已审阅且所有正式差异均已保存后，作者先进入只读“标准化结果预览”，
而不是直接持久化结果：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 标准化结果预览                              [生成标准化结果]       │
│ 5/5 已读取 · 5/5 已审阅 · 3/3 来源差异已保存                      │
├────────────────────────────────────────────────────────────────────┤
│ [审阅事项]  [审阅结论]  [标准化文档]                              │
├────────────────────────────────────────────────────────────────────┤
│ 审阅事项：全部待补充资料和全部已处理决定。                         │
│ 审阅结论：固定九章；每章内按数据库、GitHub、业务说明、ERP制度、    │
│           企业术语图完整保留来源内容和对象目录。                  │
│ 标准化文档：[阅读版] [Markdown 源文] [复制 Markdown]；完整九章、 │
│           每章五个明确来源区段，相关决定追加在对应章节。          │
└────────────────────────────────────────────────────────────────────┘
```

三个页签绑定同一份由 `runId + 精确来源 revisions + 决定清单 + Preview SHA256` 确定的
合并文档；它们是不同阅读投影，不是三份独立拼接结果。合并顺序固定为九章顺序、章内
五来源顺序，不做语义去重或内容省略。Preview SHA256 是来源清单、决定清单、合并文档
和三页签投影的规范 JSON SHA；点击“生成标准化结果”必须提交该 SHA，运行时重算同一
投影、拒绝任何不一致，并要求实际保存的合并文档引用与预览相等。生成成功后页面、页签和阅读位置保留，唯一
Primary 依次变为“确认结果并定版”“前往 AI 建模”；已交接结果仍可只读查看。

## 设计不变量

- 不恢复两页签、自动进入下一来源或完成后关闭文档。
- 不重做工作台外壳、助手、右栏、时间线或九章阅读器。
- 差异层在任何时候只有一个 Primary：保存当前决定。
- 结果预览、已生成结果、已定版结果和已交接结果展示同一份完整合并文档；仅状态和
  唯一 Primary 改变。
- 已保存决定保持可读；历史文档只读。
- 每个可见操作必须发出命令、导航或展开内容。
- 普通启动、测试、构建和浏览器故事仅使用提交的冻结资源。
