# 页面操作层级

- Demo 允许多个浏览器标签访问同一业务工作区；运行时会拒绝陈旧 revision 的保存并提示刷新。跨标签实时同步、竞争胜者恢复和协同编辑不属于本轮演示范围，作为后续 TODO。
- 每个视觉区域最多一个主按钮；行级最多一个常显“查看／编辑”。
- 真正返回父层的控件统一使用只有左箭头的 `BackAction`：它保留可访问名称“返回…”，Tooltip、40px 桌面／44px 触屏目标与触发项焦点恢复，但不显示重复的“返回来源列表／返回标准化工作区”等文字。关闭抽屉或弹窗仍使用 X，取消、分页和业务命令保留文字。`打开正式模型`、`查看数据标准化证据`、`继续编辑`是业务动作，不得伪装成返回箭头。
- 管伊佳运行前的“运行来源”保持数据库、代码仓库、官方业务文档、ERP 管理制度、术语图的固定角色顺序。左侧只显示读取状态和异常；右侧默认“实例”、次级“连接器”。连接器家族只能“创建实例”，已连接实例才可拖入兼容角色或使用等价的“添加到来源”动作；待配置和连接失败实例只提供配置。运行开始后移除、替换、配置和拖拽全部锁定；运行来源页不提供扫描或冻结。
- 管伊佳来源差异不阻断后续来源读取。用户从时间线显式打开差异时，现有 Review Surface 栈在来源文档之上临时显示差异层：它只并列当前／新来源的可读结论，并提供“保留当前结论／采用新来源结论／登记为缺口”三个决定；“登记为缺口”默认选中。系统在后台将负库存映射为兼容合并策略、将欠款和状态语义映射为延期缺口，并生成审计摘要。选项下方固定保留业务可读的 Git 风格 Markdown 变化预览：保留以绿色标出继续生效的准确段落，采用显示红删绿增，登记缺口保留当前段落并绿色新增缺口段落。它不展示原始审计 Diff、中文理由、内部策略、对象 ID 或 SHA；切换预览不得卸载决定区、抢走焦点或改变工作区滚动位置。差异层唯一主按钮为“保存当前决定”，隐藏下层“审阅下一个来源”；关闭后恢复来源文档、页签、滚动位置和来源主线。保存后自动定位下一项；最后一项保存后才进入结果阶段，不自动载入下一来源。
- 管伊佳审阅助手是工作台第二行的底部输入区，紧接主审阅滚动区；它不使用 fixed、sticky 或覆盖定位，因此不能遮挡正文、剧本卡或唯一下一步动作。展开历史时，历史区域在助手内部受限滚动，输入区始终留在同一可视工作台内。发送只用普通图标；助手可以解释事实、打开目标和生成结构化修改预览，不能从自由文本应用修改、解决冲突、冻结、交付或触发 M4。
- 助手 Patch 待确认时，“确认并应用此修改”是主区唯一 Primary；“完成本份审阅”、冲突 Primary 和“修改本项”入口暂时隐藏。编辑卡已打开时不能生成第二份 Assistant Proposal。
- 管伊佳右侧“来源资料”区上半区始终展示本次运行的五个来源及其审阅状态。每行都映射到同一来源的业务检查点；点选只在右栏选择并定位该检查点，不打开文档、不清空当前结论或依据选择，也不滚动主审阅区。下半区将审计记录压缩为每个来源一行、每项来源差异一行和一条结果，即“来源／差异／结果”三类可回看的业务检查点。右栏不承载 DDL、SQL、代码、制度段落、三元组或结论详情；跨来源的双方材料只在对应“查看双方资料”按钮下方原位展开。不得出现策略、理由、应用按钮、结果编辑器或完整 Markdown。SHA、content ref、内部来源编号、`FROZEN_FILE`、权威等级等技术值只保留在内部审计存储，不进入业务页面。
- 当前任务卡和时间线来源文档回执是“继续审阅”的显式入口，点击打开精确 document revision；“来源资料”的来源行不是文档入口。资料区由工作台标题区唯一的“来源资料／收起来源资料”控件开合，内联区没有重复标题或关闭盒；抽屉或全屏层才保留图标关闭操作。
- 来源文档默认以“审阅事项／审阅结论／标准化文档”三页签阅读。审阅事项只呈现待核对任务、逐项资料缺口和已处理决定；审阅结论只呈现核心业务结论与默认展开的完整对象目录。Markdown 标题、内部对象名、只有位置的记录和重复元数据都不形成卡片。点击“采用推荐修改”会原位打开只包含可修改字段的编辑器；点击“查看来源依据”才会在同一结论下展开全部相关摘录。证据始终属于其结论，不形成独立的“来源材料”统计或阅读区域。标准化文档保持当前 Revision 的 V6 九章阅读版；“Markdown 源文”按同一 Revision 逐字只读展示。两个视图共用同一组结论与锚点，修改后同步切换，阅读版不重复任务、来源按钮或跨来源发现。底层仍校验“来源材料 → 审阅结论 → Markdown 段落”链路，但不为它单独制造页面。跨来源发现按来源准入顺序显示：资料缺口留在审阅事项，其余判断留在审阅结论；实际审阅列宽度大于 1055px 时为五列表格，720–1055px 为无卡片墙的扁平双列行，低于720px为单列；“查看双方资料”在当前发现下原位展开。该阈值以审阅列而非浏览器宽度为准，因页面外壳会占用导航与内联资料区空间；任一宽度都不能依赖横向滚动才能使用。页头只保留一个下一步动作：有待核对剧本时为`核对 N 项建议`，可完成时为`完成{来源}审阅`，已审阅且仍有待阅来源时为`审阅下一个来源`。完成审阅不会关闭当前文档或自动进入下一来源。
- 修改摘要的空状态必须直接说明业务结果，例如“本次没有修改审阅结论”；不得把“没有可定位的识别结果差异”这类内部投影能力描述带入用户页面。普通编辑器只说明本次允许修改的业务字段，以及确认后会更新哪一段审阅文档。
- 标准化的旧入口和零售路径同样只能显示业务化步骤：读取资料时说明“确认资料范围和可读取状态”，检查时说明“检查资料、结论和审阅文档是否对应”。存储、完整性、revision 和底层异常只用于内部判断；页面只显示可执行的错误提示，例如重新打开资料、刷新当前步骤或检查浏览器存储权限。
- 管伊佳进入交付阶段后隐藏审阅助手和来源编辑动作。主区按状态只允许一个 Primary：`READY_FOR_OUTPUT`“生成标准化结果”、生成后运行作者“确认结果并定版”、`FROZEN` 作者/Admin“前往 AI 建模”；`HANDED_OFF` 保留“查看交接内容”。已登记的资料缺口和无法确定项写入完整 Markdown，但通过结构化资格排除于建模候选，不能阻止定版；缺失来源、损坏正文或未保存决定仍会阻止定版。旧 `AWAITING_INDEPENDENT_REVIEW` 数据可以兼容显示为“历史结果待定版”，但新 Demo UI 不显示独立审核入口。
- 交付事件补登失败时隐藏所有下一阶段动作，只向原命令 actor 显示“继续完成上一步”这个 Primary；恢复仍重查当前角色。交付页只呈现人类可读的来源审阅、治理决定和模型检查摘要；合并文档、决定清单、治理附录与 zero-delta 原文仅用于内部审计，不能以次级入口把 JSON、SHA 或内部引用带回业务页面。
- 交付阶段右侧“标准化结果状态”必须提供可见入口：处理中为“前往当前步骤”、待定版为“查看标准化结果”、已定版为“查看定版记录”、已交接为“查看交接内容”。交付页只展示人类可读的可建模结论、已排除事项和正式模型状态；core／Artifact／zero-delta refs 仅内部保留。历史 zero-delta Receipt 仍只读兼容，不能改变新标准化文档交接的建模资格过滤。
- 复制、启停、维护和删除放入“更多”，危险操作必须二次确认。
- Tabs 和 Segmented 只切视图，不触发学习、发布或删除。
- 批量动作只在存在选择时出现；搜索保持可见，不用“筛选”按钮隐藏。
- 抽屉固定底部“取消／保存”，桌面限制设计宽度，手机使用全屏宽度。
- 720px 以下的编辑抽屉强制单列表单，底部操作区保持 sticky 并预留安全区；抽屉层高于底部导航，开启期间底栏不参与操作。
- 技术编码、内部表达式和执行契约默认折叠；首屏使用业务语言。
- AI 建模的候选模型卡只显示业务名称、业务说明、可读状态与“已关联 N 处来源材料”；对象编码、字段编码和来源 ID 保留在内部投影与可定位材料中，不能直接作为卡片正文。
- 正式模型不可变：左侧只显示发布回执，右侧只显示一个可搜索、可跳转的对象浏览器。
- 顶部只显示模型项目与 Catalog；协作空间由项目归属自动确定，并继续作为后台权限边界。
- AI 输入框固定在左侧底部；展开右侧浏览器或发布记录只能压缩对话记录，不得遮挡输入框。
- 管伊佳审阅助手 Textarea 最多 5 行，首次只展开最近 20 turn 及本页 Proposal；当前待确认 Proposal 即使落在 20 条之外也只以一张页内卡替换普通 Turn，不读取其他页外完整 Proposal。主审阅正文保持唯一纵向滚动区；只有用户展开的助手历史在受限高度内滚动，窄屏也不能覆盖当前剧本卡或唯一下一步动作；关闭助手上下文或文档子页后恢复草稿、滚动与触发元素焦点。
- 管伊佳的 Timeline、Document、Conflict、Assistant Patch、Deliverable 与 Inspector 必须通过同一 review-surface 栈打开／关闭。实际工作区可用宽度至少 1136px 才使用内联资料区，720–1135px 使用 overlay，小于720px（含真实200%缩放后的 visual viewport）使用 `100dvh` 全屏子页。overlay／full-screen 先解除底层 inert 再恢复 stable anchor 和 focus；desktop inline Inspector 不锁焦点。
- Review 列表默认 20、Timeline 初始最多 40、任一页最多 50、前端窗口最多 80。列表行只渲染 summary；Evidence、Markdown、助手 Proposal 与交付正文只能在用户展开时读取并校验。业务页面只显示人类可读的位置；技术 ID、hash 与原始 locator 仅在内部审计存储中保留，完整 surface（含 Portal）DOM 不超过 300。
- `OFFLINE_NOT_CACHED`、`CURSOR_EXPIRED`、`CHECKSUM_MISMATCH`、`CAS_CONFLICT`、`QUOTA_EXCEEDED` 与 `FREEZE_EVENT_PENDING` 各自只有契约指定的恢复动作。错误使用 `role=alert`，恢复进度使用 polite live region；checksum 损坏、陈旧 preview 或 pending freeze 时不得留下竞争 Primary。
- 模型浏览器的实体、事件、字段、关系、维度和指标固定为单行六项，桌面与手机保持一致。
- 390×844 下上下文进入抽屉，列表先于详情；禁止中文逐字换行和依赖不可见横向滚动。
- 600px 以下的主导航固定为“数据标准化／AI 建模／本体／指标／更多”，更多只收纳业务规则、同义词和时间语义；底栏使用系统安全区。
- 手机 Header 为两层：第一层完整显示模型项目和版本，第二层放视图状态与用户动作；项目和版本不得缩到逐字显示。
- 指标、规则、目标、同义词和时间语义共用 `ResponsiveDataView`：桌面端表格必须声明列宽与 `scroll.x`，720px 以下改为信息卡并保留同等字段和操作；同义词每页 20 条。
- 本体、关系和值定义在手机上都是“列表 → 详情 → 返回列表”；层级与值定义保留独立入口，本体详情 Tabs 可横向滚动但单次点击必须完成切换。
