# 来源配置与证据接入契约

## 责任边界

来源管理是协作空间级深模块。它管理连接器目录、共享连接、配置修订、读取范围、不可变快照和来源审计；模型项目只消费快照 ID。它不负责候选对象审核或 Catalog 发布，也不直接修改本体、指标和规则。

页面、YAML 和 Fixture Adapter 共用同一个`SourceConnectionRevision`结构。中文页面由表单 Schema 和 revision 投影，不能维护另一份可编辑说明。配置改变只产生新 revision；旧快照、批次和 Catalog 保留原始引用。

## 生命周期

```text
选择连接器家族
→ 选择具体技术适配器
→ 保存业务实例草稿
→ 模拟测试连接
→ 发现并确认读取范围
→ 激活配置 revision
→ 流式读取并冻结证据快照
→ 加入个人草稿的建模批次
→ 来源互证与候选建模
```

陌生但格式合法的配置可以保存，Fixture Adapter 没有匹配结果时测试状态为`NO_RESULT`，不得生成虚假发现结果或快照。一个连接失败不影响其他连接。配置 Revision 严格执行 `DRAFT → TESTED → DISCOVERED → ACTIVE`；只有 ACTIVE revision 才能生成快照。新 revision 不继承旧 revision 的测试、发现或激活状态。只有`READY`或用户明确接受的`PARTIAL`快照能进入批次。

## 支持范围

目录固定包含 12 个连接器家族：关系库、数仓与湖仓、文档库、键值库、宽列与时序、属性图／RDF图、搜索、向量库、对象存储、企业内容、代码仓库和事件流。家族负责说明能力，具体技术适配器负责配置表单和持久化 `connectorTypeId`；例如“关系型数据库”下可选择 MySQL 或 PostgreSQL。Semantica 的`PROPERTY_GRAPH`与`RDF_GRAPH`为同一连接器中的两个互斥模式。直接文件上传属于输入方式，不额外创建存储家族。

零售经营的完整 R2 故事包含 MySQL、MongoDB、Elasticsearch、Semantica、MinIO、GitHub、SharePoint和Kafka 8个不可变快照；Snowflake、Redis、Milvus和Cassandra为可选模板。冻结操作只使用用户明确选择的快照 ID，并按 ID 排序计算批次指纹；不会因为连接器类型相同而自动全选，也不会要求每次建模必须接齐8类。证据不足时展示覆盖缺口；只有与确定性 Fixture 精确匹配的快照组合才能生成候选模型，陌生组合不得编造结果。

管伊佳来源中心的默认 R1 由 MySQL 与 GitHub 两个真实快照组成。`SourceSnapshot.snapshotId`直接使用采集清单的不可变 snapshot identity，而不是另造`*-snapshot-r1`别名；物理映射页显示相同 snapshot ID、connection revision 与 Manifest。官方核心文档属于标准文档 Artifact 的 AUXILIARY 来源，不作为第三个共享连接。两个协作空间读取同一模块接口，但状态、审计和默认批次互不共享。

管伊佳数据标准化在开始前使用 `SourceCenter mode="RUN_CONFIGURATION"`，但它不是通用来源管理流程的快捷入口。
左栏始终按数据库、代码仓库、官方业务文档、ERP 管理制度、术语图的固定业务顺序排列；右栏默认打开“实例”，并提供“连接器”页签。
连接器家族只能创建实例，不能拖动；实例才可以通过鼠标、触屏、键盘或“添加到来源”绑定到兼容角色。只有已连接实例可以绑定；待配置、连接失败与未连接实例留在实例区完成配置。已连接但没有本次运行所需快照的实例也可以加入左栏，但在“开始资料整理”时会以“缺少可用快照”明确阻止。一个实例不能重复绑定，空槽同样阻止开始。开始运行时，角色到实例的选择转换为既有正式来源身份并立即锁定；不改变来源顺序、Conflict 定义、V1 或黄金摘要。

连接可用性和运行读取状态是两个独立轴：`已连接／待配置／连接失败／未连接`说明实例状态，`待读取／读取中／待审阅／已审阅／存在差异`
说明该实例在当前运行中的位置。左栏正常实例只显示读取状态，避免重复显示“已连接”；状态标签同时提供文字、图标和统一颜色，红色只表示连接故障或治理冲突。预运行选择只保存 role-to-instance ID 到 `linguan:guanyijia-source-board:v1`，刷新会恢复同一选择；恢复演示删除该键并回到默认冻结实例。
该选择从不包含凭据、内容或可变来源配置。

运行来源页面只在页首说明一次“开始后选择将锁定”。已选来源卡只承担角色、业务实例、状态和可用操作；不再重复解释锁定规则。只读快照概览同样只显示来源、范围、运行状态和凭据，不额外叠加“固定范围”“只读”或“资料状态”横幅；这些限制由页面模式和可用操作本身表达。

运行中的阅读仍使用 `DemoContentReview` 的精确来源绑定。运行来源不得提供扫描、冻结、YAML 导入导出或自动补快照操作；实例的创建、编辑与连接测试属于来源管理子流程。新实例不会在普通 Demo 中自动扫描或自动获得运行快照，也不会让运行来源页成为重新读取固定材料的入口。

## 安全与溯源

YAML、localStorage、证据快照和 Catalog 都不得包含密码、Token和私钥，只允许保存`credentialRef`。配置导入先投影新增、更新、跳过、冲突和错误，确认后才落地。导出 YAML 与中文页面读取同一 revision。

每条证据结论保留连接 revision、快照 ID、证据定位、权威等级和上游血缘。Elasticsearch、向量索引及派生知识图谱不能重复计算为独立佐证。质量页面只显示证据覆盖率、一致结论、冲突、弱依据、派生依据及候选变化，不生成综合准确率。

发布侧的 Sidecar V2 冻结批次、来源、证据、Locator、主张、互证结论和对象绑定。互证结论必须能列出具体参与来源及各自主张；已处理冲突还要冻结决定人、时间和中文理由。当前连续演示在 R2 中保留净销售额退款时点、机器人流量排除和营业日归属三项冲突历史，解决后仍可追溯原分歧，不能只显示最终一致文案。

## 页面可读性与响应式

通用来源管理默认进入“已配置来源”，桌面宽屏保持列表与详情双栏。“添加来源”是页内子流程，连接器整卡可选，不再在每张卡内重复放置“配置新来源”按钮。YAML 导入／导出收进管理员“更多”，正常状态不长期展示连接数、快照数、覆盖率和派生依据四张统计卡；只有异常来源需要处理时才显示提醒。语义采集示例只说明其可见影响：用于查看资料如何整理，不会改动已保存的来源、已发布模型或个人草稿。管伊佳预运行板在 900px 以上保持约 340–380px 的已选来源左栏和候选右栏；900px 以下用“已选来源／待选来源”切换，600px 以下候选单列、详情全屏，页面不产生横向滚动。

390px 手机宽度使用真正的“来源列表 → 单来源详情”导航：未选择时只显示批次摘要和列表；选择后隐藏列表与批次摘要，详情顶部提供返回列表入口。整个页面只由`source-center-content`承担纵向滚动，连接列表和详情不再创建嵌套滚动区。

连接编号、批次编号、版本引用、快照编号、来源快照标识、配置值、读取范围、内容指纹和来源位置使用同一个`ReadableTechnicalValue`，并统一收进“技术详情”。短值完整换行，长值可展开／收起；每个值都能直接复制，不能只依赖单行省略或鼠标`title`。触发按钮使用原生 Button 语义并公开`aria-expanded`，兼容键盘和手机触摸；Clipboard API 缺失或权限拒绝时显示“复制失败”，不能留下未处理的 Promise rejection。添加来源、批次、连接步骤、快照选择、YAML 导入和编辑面板各自最多保留一个主动作。

## 兼容

旧`ADD_SOURCES`命令和旧 localStorage 键继续可读。新页面使用`ATTACH_SOURCE_SNAPSHOTS`，并以独立来源管理命名空间保存状态。迁移会复制管伊佳和零售经营的旧固定来源为 revision 1 和默认快照；旧状态、历史批次、草稿和 Catalog 不删除、不覆盖。
