# 统一语义建模管线

## 唯一输入与职责边界

页面和项目 Runtime 不再直接消费旧场景的来源 ID。建模的唯一输入是来源中心产生的不可变 `SourceSnapshot`；模型项目 Adapter 只负责把快照规范化为主张、交叉验证主张、生成候选模型以及把候选应用到当前用户草稿。

```text
共享连接配置 revision
→ 测试
→ 发现并确认读取范围
→ 激活
→ 不可变来源快照
→ 冻结证据批次
→ EvidenceClaim
→ ReconciliationFinding
→ 标准建模文档来源修订
→ 人工决定修订
→ 作者确认／异人审核／完整性冻结
→ M4 CandidateModelSnapshot
→ 个人草稿
→ 变更申请
→ 不可变 Catalog
```

旧 `ADD_SOURCES` 和旧场景 Runtime 只作为兼容读取 Adapter 保留。标准建模文档 Runtime 负责来源累积 revision、批量人工决定、作者确认、异人审核、冻结和 M4 幂等交接；每条修改命令校验 artifact revision 乐观锁。M4 只按冻结 artifact 的精确 SHA 编译和物化，不能直接从项目编码选择 Fixture proposal。

## 确定性 Fixture 边界

- Adapter 必须按实际附加的快照组合选择 Fixture。
- 缺少来源时只生成覆盖缺口、单一依据或弱依据，不得引用缺席来源。
- 陌生但合法的来源配置可以保存；陌生快照组合显示“尚无预生成结果”。
- 在收集阶段移除来源时，该来源、Claim 和 Locator 必须同步形成负向 delta 并从当前视图消失；已经冻结的批次不允许原地移除。
- Elasticsearch、向量索引和派生知识图谱保留上游血缘，不能重复计算为独立业务真相。
- 每个证据 ID 只能属于一个来源和一个 Locator；检查失败时禁止冻结或发布。

## 两个项目，共用一条状态机

零售经营以正式 V1 为基线。八个来源依次形成标准文档 r1-r8，三项人工决定形成 r9，经作者外审核和完整性门禁冻结后才能进入 M4，再由 Kenan 提交、Zhengqing 审核和 Hao 发布形成 V2。

管伊佳的规范 V1 是证据基线：最新 MySQL、固定 GitHub master Commit 和官方核心文档先生成 Claim、冲突决定、完整九段 Markdown 与签名语义载荷，再由 M4 唯一 projector 物化为 Catalog。系统基线发布回执不冒充用户审批；后续任何修改都从该 V1 新建个人草稿，并继续遵守作者、审核者、发布者分离的状态机。旧的 MySQL→GitHub r1-r2 演示只保留为兼容测试，不再作为正式页面的第二数据真相。

项目差异只存在于 `ProjectModelingAdapter` 的 Fixture 数据与业务规则中。来源中心、AI 工作区、资料／互证／模型检查器、协作权限、草稿、审核和发布均不允许按 `systemCode` 复制页面分支。

## 业务页真相

- 物理映射只读取当前项目、当前草稿或 Catalog sidecar 所引用快照的 Manifest。
- 无脱敏样例时不显示“数据预览”，也不能生成示例值。
- 规则候选是只读待结构化对象，不属于可执行规则列表。
- 指标保留公式、依赖、聚合与编辑能力；复杂或不兼容指标保持只读。
- 时间规则保留来源、范围和偏移，不能用固定日期或覆盖率替代。
- 本体关系在业务页面使用“一对多”“正向”“仅保留匹配记录”等可读文案；内部枚举仅作为保存值，不能作为表格、卡片或编辑器的显示标签。
- 面向用户导出的审阅说明书只包含来源名称、材料位置、可读结论、比较结果与建模建议；原始 JSON、校验摘要和内部对象编号留在审计存储，不进入说明书或下载包。
- 管伊佳正式 V1 的可执行规则和日历为空；8 条规则只进入只读“待结构化候选”，9 条时间语义只表达有证据的业务时间字段，不生成营业日、节假日或 SLA。
- 正式和历史 Catalog 通过显式 read-only 能力禁止修改；命令层仍必须返回可读拒绝。

Catalog 的 Sidecar V2 冻结实际批次、快照、主张、结论、Locator和对象证据绑定。旧 Catalog 缺少这些数据时显示明确的历史覆盖提示，禁止从最新 Fixture 反推。

标准文档 M4 物化若基于 Sidecar V2 Catalog，先按业务身份更新已有对象；新增可见对象必须同时生成一条持久`objectEvidence`绑定。没有精确支持边时只能标记待确认，不能按 Evidence 共现猜测支持。发布检查对所有可见对象执行证据／待确认 XOR，并拒绝缺失、孤儿、批次外 Evidence、缺失 Claim 或 Evidence 未被绑定 Claim 覆盖的状态；Sidecar 的项目编码也必须等于申请模型项目。
