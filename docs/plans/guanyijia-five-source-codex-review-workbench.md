# 管伊佳五源标准化故事与 Codex 式审阅工作台

## 目标

将数据标准化改为逐源读取、逐源生成九段式 Markdown、结构化审阅、Git 式冲突解决、输出定版和 AI 建模交接的连续工作主线。主演示使用管伊佳 MySQL、GitHub、官方核心文档、演示制度 Markdown 与派生 Semantica 五个来源；现有管伊佳正式 V1 和零售正式版本保持不变。

## Checkpoint

1. 标准化运行、事件和逐源编译接口。
2. 管伊佳五源 Fixture、来源文档和派生图血缘。
3. Codex 式主时间线和右侧事实检查器。
4. 结构化文档审阅与真实 revision Diff。
5. Git 式冲突解决和最终语义 Patch。
6. 真实审阅助手与按钮减法。
7. 输出定版、M4 零变化交接和黄金 V1 保护。
8. 响应式、容量、E2E、文档及独立代码审查。

## 全局约束

- 每个来源按固定顺序读取，生成独立九段式文档；文档审阅完成后才进入下一来源。
- 结构化块、断言与 Markdown 同事务更新，旧 revision 不覆盖。
- 冲突决定必须产生真实结构化 Patch 和 Markdown Diff，不能只解除门禁。
- 主区承载过程、文档和冲突；右侧仅展示来源、证据、血缘与已确认结果。
- 恢复的对话输入只能执行可审计的查询、导航和修改预览，任何修改必须再次确认。
- 演示制度与派生 Semantica 不进入管伊佳正式 V1 证据链；派生来源不增加独立佐证数。
- 交给 M4 后与正式 V1 比较为零语义变化，不创建草稿或 V2。
- 管伊佳黄金结果保持 14实体、9事件、296字段、30关系、4维度、5指标、2层级、8规则候选、10同义词、9时间语义、63待归类资产、2排除项。
- 只修改 linguan-prototype-v2，不部署远端。

## 固定主演示

1. MySQL：部署物理事实与库存时间缺口。
2. GitHub：Mapper、Service、迁移与真实 debt 字段冲突。
3. 官方核心文档：业务名称、活动、层级与时间解释。
4. 演示制度 Markdown：负库存制度和状态9含义的故意差异。
5. Semantica：由演示制度派生的术语图，保留上游血缘。

冲突固定解决为：部署结构优先并继续排除应收欠款；负库存保留按租户配置的实现事实，制度记为未落地目标；状态9保留字段和规则候选但不发布正式枚举成员。库存生效时间保留为证据缺口。

## 验证

按新增模块定向测试、既有 source-management/semantic-evidence/data-standardization/modeling-document/ai-modeling/collaboration/catalog-browser 测试、fixture check、TypeScript、核心 E2E、响应式 E2E 和 diff check 的顺序执行。
