# 相关证据能否帮助识别业务联系：轻量POC详细设计

状态：2026-10-01，**实验已结束，当前未通过跨入口联系验收**。财务4次得到准确但有限的查询侧结果，未读写入桥接；采购2次停在空包的保留编号校验。见[实际验收结论](../../supplements/light-relation-probe-20261001-acceptance.md)。不扩大正式实施，不把协议失败说成业务推理失败。

用户随后确认“要求说明关联如何建立”，批准[关联建立机制薄实验](relation-establishment-poc.md)。它使用独立批次，最多追加5次；本文旧四阶段实验及原始结果不改，不将新合同追溯为旧题目要求。

[已有零模型测量](../../supplements/entry-overlap-probe-20261001.md)取得20入口、190对技术重合结果；它只证明集合可计算，没有证明模型选材或关系识别成功。[总体设计](README.md)及[类型化局部合同](assemblable-scope-experiment.md)保留为后续目标，本POC不冒充其验收。

## 1. 要回答的问题

**给模型20个真实入口的简短清单，以及它们的共同材料和频次，能否引导它选到原文，并核对一条具体业务联系？**

本轮不另跑只有接口名称的对照模型请求，因此只能判断这条路线在受控范围内是否可行，不能宣称它比旧路线更准确。

接受以下两种导航依据：

- 程序已经算出的各维度重合、共同材料和出现频次。
- LLM据这些资料给出的粗略“优先调查／可能相关／只见公共项／无法判断”。

不要求校准到精确百分比。不把分数当业务关系概率，不调一套复杂权重。最终仍须读完整原文并核对；估算得好但关系写错，实验不通过。

本次最低交付是**有来源的关系核对结果与明确失败原因**，不是完整六类本体。方向成立后，才将它接入对象、关系、操作、维度、度量、指标的现有类型化任务。不能把几段关系说明宣称为已经生成本体。

## 3. 最小实现：三个已有能力＋一个临时驱动

| 负责者 | 本次做什么 | 不做什么 |
| --- | --- | --- |
| 现有Corpus/读取器 | 严格重开R4/R0，查单元、字面搜索、取完整原文 | 不重建Java/XML/SQL解析器 |
| 已有重合度探针 | 提供20入口共同项、各通道重合及全仓频次 | 不开发聚类、图数据库或业务规则评分器 |
| 现有Provider/保存底座 | 调用Luna/high，保存实际输入输出和身份 | 不由宿主Agent代写答案后导入 |
| 薄实验驱动 | 按下述固定阶段串联；核对引用与容量 | 不新增正式CLI、公共Agent或恢复框架 |

沿用现有Provider接口、JSON处理和单元读取。现有`OntologyDecisionRunner`只接受既有导航视图，`OntologyQuestionExperiment`还要求前置对象任务；它们不能不改输入就直接执行这个新探针。因此使用一个临时的四阶段请求适配，不冒充现有类型化任务已经通过。实验程序放忽略的独立POC目录，不改当前SURVEY/PRIORITIZE/READING或正式业务算法；不先为每一个小职责创建Module。

## 4. 模型首次看见什么

每个入口是一张短卡：

- HTTP方法/路径、Controller处理方法、组装状态及实际限制；
- 方法、Mapper/XML、已解析表等线索数量；
- 少量可请求完整单元的标题、大小和短引用；
- 与其它入口的具体共同材料、频次及已有J/W；
- 已保存的前端页面、实例、实参和候选地址限制。

长身份留在程序映射中，模型用当前视图的短引用。原文引用与导航引用分开。源码/注释是数据，不是新的执行指令。

设计目标是让具体共同项和频次辅助选材，不按采购词、金标准路径或正确答案排序。**本次实际只显示分通道统计及每入口少量线索；线索按Corpus的lookupKey选取，没有实现罕见共同项优先显示。**只显示部分线索时列出总数和未显示数，允许查详情。单元使用次数与重合报告的不同入口频次分别说明。

首次必须显示全部20张基础短卡，包括四个对照入口；不能静默移走入口或对照材料。**本次实际附上全部190对的紧凑14通道统计，未附逐对共同材料名称清单。**通道名称用可逆短编号，小数用可还原数值文本，未测值保留null。财务首次输入122,532字节，采购122,660字节，未宣称适合任意小上下文。若卡片超限，容量预检失败；另定更小范围须明确冻结新名单，不能继续报告为20入口通过。不剪完整源码。

LLM可估算相关度，但输出只是调查建议：

```text
候选入口对或入口小组
优先级：优先调查 / 可能相关 / 仅见公共项 / 无法判断
理由：具体共同材料、实际用法或仍未知的部分
需要读什么：合法单元引用与读取目的
```

这不是预期模型答案。首次看见同表，只能说值得核对，不能直接宣布同一对象、状态依赖或先后流程。

## 5. 两个小问题，逐个执行

不一次运行完整六类任务。先做F，查看完整结果后才启动P；每题最多四次模型请求，无自动重试。

| 题目 | 给模型的普通问题 | 不提供什么 |
| --- | --- | --- |
| F：财务 | 财务记录如何关联业务单据、相关金额如何计算并影响欠款？请先选择其中一条有界的跨入口联系核对，其余范围列为未调查。 | 正确Controller、字段、原文路径、关系答案 |
| P：采购 | 采购相关单据与其它单据、库存或资金记录有哪些联系？请先选择其中一条有界联系核对，其余范围列为未调查。 | 固定请购→订单→入库→结算顺序、正确状态或接口清单 |

两题共用同源原始资料，但P不继承F的模型结论或定向阅读包。两题都是有问题提示的受控实验，不称无提示发现。

### 阶段1：估算相关性并选择首批材料

输入普通问题、20入口短卡及技术重合线索。模型选择一个有界联系，说明相关性估算依据，提出少量完整单元或有限查询请求。

程序执行实际读取/查询，保存合法短引用、原文身份、实际取得与未取得范围。可能相关入口不自动变成全部Controller必读清单。

### 阶段2：看原文，最多补读一次

输入首次读回的完整原文及实际查询页。模型指出哪些材料相关、哪些仅为公共工具，是否需要补读具名单元。

程序最多执行这一轮补读。提取阶段收到补读后的完整包，不用摘要替代源码。如果第一轮只查了目录，第二轮才读到正文，也如实记录；这不保证材料充分。仍缺原文时后续只能返回局部观察/未通过，不能被包装成完整关系。

阶段1可请求完整单元或有限目录/字面查询；阶段2只读取已可见的N编号完整单元。本次每页25项与全轮限制最初有歧义，采购保留原始选择后明确为最多两页、共50项目录；正文仍最多70,000字节，每题最多4次请求。后续合同必须分别命名每页与全轮限制，不靠提示词猜含义。最后一轮若仍只有导航/查询页、未读到必要正文，停止为阅读未完成，不派发阶段3、4。

### 阶段3：给出具体联系，不写大篇文章

输入普通问题、同一个封闭完整包。返回少量结构化观察：

- 两端涉及什么对象或业务用途；
- 通过什么标识/字段传递、保存、查询或修改；
- 条件、分支、拒绝、适用入口/页面参数；
- 相关金额的计算和过滤；读到了才解释；
- 具体原文引用；
- 不成立的候选、缺材料及仍无法确认的部分。

临时响应只用于判断路线，复用现有合法引用/保存能力，不先建设完整本体Schema。不能读中文自动合并对象，也不生成执行规则。

### 临时适配合同：只够这四阶段使用

采用一个小型JSON Schema，不扩展正式本体合同：

| 阶段 | 返回内容 |
| --- | --- |
| 1 | `candidates`（入口短编号、优先级、具体理由）、`requests`（查询或完整单元读取、短引用、目的、有界参数）、`selectedQuestion`、`unknowns` |
| 2 | `retainedRefs`、可为空的`requests`、`unknowns`、`readyForObservation` |
| 3 | `observations`（两端用途、关联机制、标识对应、条件、方向、实际读过的原文引用）、`rejectedCandidates`、`uninvestigatedScope`、`unknowns` |
| 4 | 完整修正后的阶段3结构及`corrections`；没有修改也返回完整结构 |

不适用的阶段字段不接受。观察可以为空，此时不能标记关系核对通过。这里的两端是待核对的描述，不是正式对象ID；不存在前置对象定义依赖。

薄适配保存两套可逆短引用：导航引用只可选材和查询；原文引用只对应已经读回的完整单元。查询的新线索和映射在下一请求显式可见，不让模型猜编号。模型原始响应不改写；规范化结果另存。来源引用错类、跨包或未读即引用时明确失败，不自动修补语义。

每次请求保存阶段、问题、20入口名单、实际卡片/包、映射、Prompt、Schema及模型身份；这些实际值连同R4/R0参与journal匹配。复用现有保存底座，但不把临时观察写成`ontology-typed-job-result`，不复用旧调查答案。只做必要结构/引用/容量检查，不增加恢复、重试或审批系统。

### 阶段4：对原文审阅

输入相同完整包＋阶段3的实际输出。返回完整修正结果和修正理由，可拒绝关系或降低为未知。

最终只用审阅稿。没有WRITE、没有最终润色、没有“再调用一次试试看”。结构校验通过后，人审对照原文检查关键结论，不能以JSON合法代替业务正确。

## 6. 状态写入→另一入口读取，怎样验证

本次不先实现全仓状态读写索引。当前SQL AST存在空值/部分解析；`/depotHead/list`的动态status条件没有进入已保存SQL结构，因此不能只比较AST得到完整联系。

程序提供已有同表/同方法/同语句导航，或模型自行提出的字面搜索命中；字面命中标为TEXT_HIT，不标为READ/WRITE。模型读完整Java和XML后，才解释写入、读取、筛选或动作判断。

人工验收已有一个具名锚点：

- `/depotHead/batchSetStatus`原文包含状态赋值、按id集合更新及对应XML；
- `/depotHead/list`原文包含status拆分及XML的if/foreach状态筛选；
- 它们Service重合只有2.7%，所以低相似度不能自动排除。

这个锚点只供验收，不送模型或预填读取清单。即使模型找到了两边，仍须区分“修改字段后影响筛选条件”与“必然触发下一个业务动作”；记录范围、类型/删除等条件未核对时保留未知。

## 7. 必须检查的反例

1. **公共方法假关联：**单据列表与导入客户共享User/会话方法。可以报告共同技术材料，不能据此批准业务交接；不靠日志/权限名称黑名单。
2. **低重合但有联系：**不能因为上述状态例子的分数低就不允许调查。
3. **同入口不同页面用途：**请购、订单、入库页面共用`/depotHead/list`，但requestId、pagePath、instanceKey、type/subType/status及未传参数不同。不能合成四个后端入口，也不能合成同一动作。
4. **候选地址：**现有前端请求有未确认的baseURL条件，不能从候选升级为已确认部署链。
5. **部分SQL：**完整XML保留而AST缺条件时，不能说无条件/无关系，也不能假装已执行最终SQL。
6. **相同Controller/表：**只见粗重合时，应能保留未知或拒绝联系，不拼固定生命周期。

## 8. 通过、失败及结论边界

不要求粗略分数精确。检查两个更重要的结果：

| 检查 | 通过 | 失败 |
| --- | --- | --- |
| 候选选择 | 共同材料和用途有可复核理由，未被公共项明显误导 | 只凭接口同名或Controller同类硬连 |
| 原文取回 | 所选完整单元确实进入阶段3、4，限制/用法未丢 | 只看到标题便写关系；关键材料未读 |
| 关系机制 | 标识、动作方向、具体条件有原文；未知说清 | 只有“共用表/相关业务”空话，或改错关键规则 |
| 审阅 | 原文核对能修正/拒绝具体错误，最终保存修正稿 | 原文已读仍保留关键错误 |
| 反例 | 公共工具、页面变体、动态限制处理不离谱 | 无关材料被强接，候选升级确定链 |

财务验收核对[现有人工走查§4](evidence-walkthrough.md#4-重点跨controller的业务联系)，至少应有一条具体的跨Controller标识交接或同一记录使用机制；只解释财务头和明细的父子关系不足以回答本轮问题。只核验实际选中并读到的范围，不能要求四次请求内证明金额、欠款及所有联系的完整闭环；未调查的部分必须列出。该人工答案不进入模型输入。采购也只核对选中的一条真实交接/字段使用联系，不强制覆盖分批、状态、金额和完整生命周期。

结果只允许：

- **值得继续：**受控范围内，估算导航能引导读到材料，审阅后的具体关系成立，关键反例未误判；可以设计正式接线。
- **需要定位：**原文存在但未读到，或容量/引用阻断；列具体断点，不说模型已读后推理失败。
- **本次不通过：**读到仍误判关键机制/规则；不扩大实施。

没有严格A/B真实模型重复实验，就不报告准确率提升百分比。20入口人为范围不证明全339入口发现；关系通过不证明对象/关系/操作/维度/指标已全部可组装。

## 9. 容量、调用和记录

初始沿用已有POC请求/包字节边界，并在每次派发前检查实际Prompt、Schema、输入、审阅稿和输出余量。字节检查不是上下文证明；必要完整单元超限就停在具体问题，不自动换大模型或剪原文。

两题上限`2×4=8`次，无自动重试。本次实际财务4次、采购2次，共6次；旧额度累计为21/26。财务第4次是未曾派发的原定REVIEW，采购没有重发SELECT；原始停点保留，协议调整和实际继续范围见验收记录。剩余额度不表示可自动派发新实验。

完整六类本体的新导航实验仍需另定计划/额度：新SURVEY不能复用旧回答，现有四任务从空包出发的最低为H＋17，H是实际新调查页数。**本次不做这项开发或调用。**

保存独立实验清单、原始请求/响应、真实模型身份、每次查询/读回、完整包/映射、审阅修正及简短验收记录。复用现有journal，不覆盖旧记录，不安装正式ontology.json，不新增公共版本合同。

## 10. 下一步与停止点

1. 零模型：复用已有20入口重合报告，生成可见短卡，核对真实Corpus可读及实际输入容量。
2. 具名运行F：最多四次，完整核验并展示。失败先给出具体断点，不自动修稿。
3. F具备继续价值时再运行P，最多四次；仍只使用固定证据。
4. 汇总“能否找到材料、关系是否准确、哪里未知”，再决定正式设计/实施。

本POC不先开发全仓相关分组、精确权重/阈值、字段读写分析器、正式四本体CLI或新证据系统。只回答方向是否值得继续，不能因为已经写过重设计而逆向合理化保留它。
