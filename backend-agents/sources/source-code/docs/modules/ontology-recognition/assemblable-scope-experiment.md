# 可组装本体的小范围实验合同

当前离线修正（2026-10-01）：每轮READING现按用途列出可保留的已读单元、可请求的导航完整单元，以及各查询种类可用的键，并告知还剩几次阅读决定；Java仍严格校验，不会把错误类别的引用自动转义。最后一轮产生查询页却无下一轮选择时，结果明确为`INCOMPLETE / ONTOLOGY_READING_ROUND_LIMIT_WITH_UNREAD_NAVIGATION`；查询页虽保存在阅读观察中，却不算已读原文。OBJECT阅读同时收到本批已选任务的问题及其**导航并集**；同页不同入口不会因按页去重而丢失。OBJECT阅读未完成或未识别对象时，不派发依赖对象的后续任务。四类任务都返回后，若对象、关系、操作、维度、度量或指标缺失，局部组装仍可保存为待审副本，但实验状态必须是`INCOMPLETE`。这些只通过scripted定向测试验证；尚无新的真实模型重验，不能宣称已取得局部本体。

空包起步时，每类至少一次阅读决定选择完整单元，再一次在看到原文后决定能否提取。因此六页SURVEY精确复用时，P3四类任务无失败至少需要`1次PRIORITIZE＋8次READING＋8次EXTRACT/REVIEW＝17次`新请求。此前“至少13次”漏算第二次阅读决定。五批次累计15次派发，原26次累计上限只剩11次，不足以完成这次四类真实验收。本次离线修正没有增加模型调用；若要验证业务质量，需另行确定具名额度。

状态：2026-10-01。现有R4/R0只读材料上的离线合同和scripted全链已接通；旧P1/P2i原始记录未改写。真实P3第三批次完成六页调查但只选了RELATE；第四批次选四类却超出未告知的分页上限；第五批次OBJECT两轮阅读仍缺材料，RELATE首轮混用引用类别。原始响应和缺口已保存；离线合同已修，尚未真实重验。五批次累计15次派发，原26次上限余11次，低于空包四类任务至少17次的新调用要求。仍无已审局部本体，更不能宣称全仓本体完成。本文只规定实验，不授权正式O0–O3发布。

## 要回答的两个不同问题

1. **无提示选题覆盖：**从原始 R4 导航出发，模型提出了哪些有来源的问题。未提出某个隐藏联系，是发现覆盖问题，不是读过原文后推理失败。旧 P2i 记录仅作这项基线。
2. **普通业务问题的自主取材与表达：**只给“财务记录如何关联业务单据、相关金额如何计算并影响欠款”，不提供入口、文件、字段或答案。模型自己选择阅读范围；读完后直接返回可组装的类型化定义。此项必须用独立新批次从原始 R4 开始，不接续 P1 的人工材料或 P2i 的定向选择。

两项不得合并评分。旧 P1 的 `role/text/evidenceRefs` 是有依据的文字笔记，**不是**可组装的对象、关系、操作、维度或指标定义；旧 v1 结果只能查看，不自动转换或复用为新版。

## 实际模块与数据流

```text
已验证 R4 入口目录及同源 R0
 → OntologyEvidenceCorpus：全部入口导航、技术线索、准确单元读取/反查
 → SURVEY 每页＋PRIORITIZE 最多四题：由模型将四类任务分配给一个或多个有来源的问题
 → 每个类别独立 OntologyReadingCoordinator：有限导航、完整单元读取、保留/补读
 → OntologyReadingPacket.modelInput：短引用＋完整相关正文＋已知技术限制
 → OntologyTypedTaskRunner：类型化 EXTRACT → 同原文 REVIEW
 → OntologyScopedAssembler：仅映射结构字段和来源引用，生成待审局部 JSON
```

`OntologyReadingPacket.canonicalInput` 保留完整私有来源身份、R4 原编号、跨入口用法和内容；`modelInput` 只发送短 `E/J/C/U/R/V/B/X/S/Q` 引用、已选内容和逐入口限制计数。前端请求投影按实际 R4 字段保留 HTTP 方法、已解析路径、原 URL 表达式、页面实例、实参绑定、封装调用链及候选关联状态；不能用不存在的字段名形成空请求。前端原文、Java 方法正文、实际调用参数、XML 结构/原文及 SQL 分析一旦选中，不能截断或摘要替代。一个单元被多个入口使用时内容可去重，但各入口用途仍单独列出。调用矛盾、未解析和工具限制不得因为投影而消失。阅读检查和提取/最终审阅使用同一投影；模型不能看到私有长 ID 作为业务语义。

容量判断针对实际模型输入及 Prompt、Schema、输出预留分别执行。当前 `maxPacketBytes` 只检查编码后的阅读包 JSON 字节，**不是** token 窗口证明；超限返回具体未完成任务，不静默裁剪。分任务阅读是主要的容量控制，字段投影只做薄减重。

每次READING输入必须包含本轮`maxPageItems`。`queries`与`literalSearches`中各请求的`limit`都应大于0且不超过该值，所有这些`limit`的合计也不能超过该值；完整原文的`readRequests`不占此分页额度。模型若需要更多分页，应声明未请求范围，留待下一轮；程序仍按实际配置严格拒绝超限响应，不静默缩小模型提出的页数。旧P3续验在模型请求三页各50项、配置总上限25项时失败，根因是当时没有把此上限送入模型输入。

`retainedRefs`只能引用本轮`readingPacket`里已经读到的单元；空包时必须是`[]`。`readRequests`只能引用可见导航里的完整单元，入口引用只能用作`ENTRY_UNITS`查询键，不能直接作为待读源码。第五批次模型把导航入口/语句同时填入`retainedRefs`和`readRequests`，暴露旧Prompt未明确这两个字段的职责；当前只修正输入说明和离线测试，不把不合法引用静默改成另一种读法。

## 六类类型化定义及任务依赖

每个任务只有一次候选和一次对同一原文的审阅。最终取 REVIEW 的完整修正结果，不再写文章或额外把文字“转本体”。

| 任务 | 返回的结构 | 重要字段及检查 |
| --- | --- | --- |
| OBJECT | `objects` | 身份绑定、作用范围、唯一性依据或未知；属性、变体、来源 |
| RELATE | `links` | 已审对象两端或明确未解端点、字段/标识交接、条件、适用范围、基数依据 |
| ACTION | `operations` | 目标对象、操作类别、前置/拒绝条件和效果；查询不能被写成状态改变 |
| ANALYTIC | `dimensions`、`measures`、`metrics` | 源对象、输入粒度、计算式、聚合、过滤、空值/时间口径及组成引用 |

关系、操作和分析任务看到前面已审的对象定义，但不继承其旧阅读包的局部 `J1` 等来源编号。模型只可引用已审对象 ID；没有对象依据时只能用合同允许的未解端点/空引用，不得造新对象 ID。REVIEW 可改定义，但每项改动须列 `corrections.targetLocalId` 和原因；无法确认的问题保留在 `unknowns`、`unresolvedQuestions`，不因请求次数耗尽而变成已确认事实。

程序只查 Schema、任务种类、局部编号、已有对象/指标组成端点、来源短引用和修正记录。它**不**判断中文结论是否由代码证明；真实业务准确性仍需人核对来源。普通问题实验的PRIORITIZE最多选四个有来源的问题；同一问题可承担多类任务，但OBJECT、RELATE、ACTION、ANALYTIC每类在全部选题中只能分配一次。每类独立阅读原文，先完成OBJECT，再让其他任务使用已审对象定义。缺少某一类时记为调查范围未覆盖，重复分配时拒绝，不让Java补造或选择业务任务，也不报告局部组装完成。候选/审阅/请求/失败分别保存在私有 model-job journal，完整成功记录为 `ontology-typed-job-result-v1`；历史 `ontology-job-result-v1` 不能充当完成记录。

## 局部组装与明确拒绝

`OntologyScopedAssembler` 只消费已审类型化 JSON 和对应冻结阅读包，映射 `O/L/A/D/V/M` 局部定义 ID、对象端点、指标组成引用及来源短引用。它对任务顺序排序后输出：

- `ontology-experimental-scope-v1`：`status=DRAFT_REVIEWABLE`，六类定义和未决问题；不是正式 `ontology.json`。
- `ontology-experimental-source-index-v1`：局部证据引用如何回到准确 R4 单元和各入口用法；不向业务名称推断身份。

同名对象不会自动合并。相同局部 ID 的冲突定义、缺失对象端点、缺失指标组成或混合 R4 来源均拒绝；合法未知以合同字段明确保留。阅读检查中未解决的问题以 `READING/任务类别` 标明来源进入局部输出，且在实验 manifest 中按任务保留，不能只因最终审阅没有重复提及就消失。输入顺序变化不得影响两个输出的字节。真实 R4 片段和非 ERP 的“实验样本”fixture 均走零模型测试；fixture 的人工定义只验证合同，不是业务识别结果。

## 两道门禁与结论措辞

先过 scripted Provider：导航→逐任务阅读→六类提取→审阅→组装，业务模型调用为零。随后才可请求**单独具名授权**真实实验：同一固定 R4/R0，新批次、普通问题、建议最多 26 次请求、无自动重试。运行记录应包括每次实际输入、模型身份、容量、选材、读回单元、审阅修正、调用数和人工核验。不得把本文件当作授权。

以下为历史实验行为，不是正式O0–O3运行说明；独立驱动及`ontology-assemblable-scope.example.json`模板保留在原工作区，不随正式产品交付。历史`mode=P3`要求新配置版本、单独输出和journal目录，拒绝人工任务清单。独立运行默认不复用历史决策；只有另获具名授权时，才可用`replayDecisionJournalRoot`和`expectedReusedDecisions`精确复用同一固定输入、模型和配置下已成功的SURVEY原始响应。全部调查页必须匹配；缺页或请求内容、Prompt、Schema、模型身份不匹配即拒绝，不以新调用补足。PRIORITIZE及后续任务仍重新调用。预检要求预算至少容纳导航页数、1次选题、四类各2次阅读及各2次提取/审阅，再减去精确复用页数；额外补读仍可能超过这个最低值，Provider保留硬上限。结果只写`experimental-local-ontology.json`、`experimental-source-index.json`和带状态/缺口的manifest；缺少必需定义时即使保存了待审局部JSON，状态也必须是`EXPERIMENTAL_INCOMPLETE`。这不是正式CLI或运行发布。

单页调查的短引用校验有一项限定修正：模型如果只误抄了 `viewId`，而 `ref` 在该页的可见映射中唯一存在，且符合该字段要求的 `ENTRY`／`CLUE` 类别，程序可以在验证后的副本中把 `viewId` 改为该页真实值。原始模型响应不改写；`survey/attempt-1/validation.json` 逐项记录位置、短编号、原值和校正值，完整决策记录保存校正后的响应。短编号本身错误、类别错误、多页阅读、任何源码或业务字段均不得自动修正。该规则只消除明显的页编号抄写错误，不证明模型选材或业务推理正确。

人工重点核对对象身份如何交接、金额查询的粒度/过滤、欠款回写的条件与范围、以及模型标出的未知。必要原文超限或关键规则错误即未通过，不扩大到全仓或新建 DDL 分析。结论只能是：类型化合同失败；合同成立但自主取材失败；或普通问题下的小范围识别通过。第三种**不**证明无提示全仓发现或完整覆盖。正式四 CLI、Skill、运行存储与全仓计划须另行决定。
