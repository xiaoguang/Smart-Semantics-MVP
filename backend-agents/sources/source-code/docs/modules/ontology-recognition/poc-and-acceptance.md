# 本体识别：薄PoC、实施面与验收

适用范围：本页保存P0–P2历史实验合同及其当时结果，不作为当前正式实施的启动门禁。当前已批准的[十步正式计划](../../plans/ontology-recognition-implementation-plan.md)先交付材料框架与三个EXPLICIT局部样例；自主选材和全仓覆盖单列未验证。历史实验结果不转换成正式O1/O2，原始记录不改写。

状态：2026-10-01，固定R4/R0只读P0、薄选材49项直接测试通过；P1有五项人工选材已审文字小样。P2g的选题汇总容量断点经v3输入消除；P2i真实选题和首轮原文阅读成功，但第二轮已读方法引用不能作`METHOD_USES`查询键，0项无提示小样，G1未通过。该引用合同现已修正并经保存响应零模型检查，**没有重写或续跑旧P2i**。旧P2阅读超70KB是此前独立断点，原记录保留。新增[可组装小范围实验合同](assemblable-scope-experiment.md)将文字笔记与类型化定义分开；其真实模型验收尚未运行。正式发布未执行。[实际验收记录](../../supplements/ontology-recognition-poc-acceptance.md)维护实测结果；本文维护验收合同，不是新调用授权。只接新R4/同R0，不兼容旧分析。

## 1. PoC回答三个问题，不以文件齐全过关

1. 在有界阅读输入中，模型能否识别对象、身份、操作/规则和分析口径，而不是只翻译表名/参数？
2. 能否从全资料导航自主找到必要原文，跨Controller识别标识交接，而不是依赖人工提供正确文件？
3. 原文审阅能否发现并纠正具体错误，最终结构化内容保留规则且可确定性展示？

当前证据支持一条完整检查路径：采购来源关系、财务明细关联业务单据及欠款回写、审核条件、期间净采购额。它是验收范围，不是通用Prompt答案。业务域其它部分可以不在首轮；不得称为全仓本体。

## 2. 首轮只做三个薄部件

| 部件 | 最小实现面 | 暂不实施 |
| --- | --- | --- |
| EvidenceCorpus projection | 严格读R4/R0，身份去重，共同技术键/入口单元分页、字面搜索，完整读回与局部引用 | 图数据库、embedding、全文件重新解析、业务分类器、选择性存储优化 |
| Recognition task runner | 明确问题、有限阅读、三类EXTRACT与RELATE/REVIEW；复用现有Provider保存底座 | 外部任务导入双runtime、复杂恢复/审批、自动无限重试 |
| Validator/Publisher | Schema与ref/scope校验，输出小样JSON及确定性视图 | Foundry部署、动态对象实例、执行Action/SQL、指标引擎 |

这些部件覆盖主设计五个职责，但在PoC内允许Recognition与Linker使用同一个内部runner、Validator与Publisher相邻实现，避免为薄职责先做接口体系。正式独立操作仍以四命令合同为目标。

可先用具名内部验收驱动调用这些部件；它不得复制选材/推理算法，也不得假装已经有正式CLI、Agent运行和publication。PoC临时结果明确标为实验，不混入R4/旧业务结果。正式化阶段再验证真实Agent、运行登记和canonical安装；两种通过状态分开。

## 3. P0：零模型准备与容量检查

固定相同R4/R0、选定来源范围，输出：

- 全入口/前端覆盖分母、去重单元数、导航页范围、最大单元及内存/读取耗时。
- 业务问题所需实际阅读包、局部映射与当前限制；导航不含人工业务结论。
- 真实Prompt/Schema与审阅候选预留后的容量估算，不静默裁剪。
- 可选DDL解析结果及未支持范围。

2026-09-30已运行只读P0：严格重开固定R4的339个入口，取得40,843次可寻址单元使用、15,252个去重内容，最大完整单元159,204字节；每页64入口形成6页，最大调查输入23,372字节，删除重复导航正文后选题输入1,145字节（该次为脚本空问题，真实调查输出会增加）。4单元实际包23,361字节，scripted提取/审阅输入23,626／23,970字节，模型调用0。同R0有效文本重开约31秒。R4重开/投影约30秒，单次运行used-heap差随GC变化，**不是峰值RSS或稳定保留量**。最大单元超过建议实验输入上限，选中它时须报告容量缺口，不静默截断或以摘要代替。

PoC不要求先把全DDL解析器补齐。选定原文可经R0供模型读取；若没有安全单元边界或无法容纳，保留限制、使用代码/SQL身份依据，不冒充DDL约束已确认。DDL方言扩展仅在成熟工具评估有明确收益时另议。

## 4. P1：已知材料对照，验证推理与审阅

使用走查中已核对的具名单元，测试“材料充分时该路线能否输出正确结构”。人工选择的输入必须在报告中声明。

最小覆盖：

- 对象任务：业务单据头/明细及请购、订单、采购入库变体；身份/关联键与未知。
- 操作任务：审核/反审核，或采购关联与明细保存的具名分支；状态、拒绝与条件效果。
- 分析任务：采购及退货measure、净采购metric与时间/筛选维度。
- 关联任务：财务明细与业务单据的标识联系及条件回写。
- 各任务完整原文REVIEW；不增加正文WRITE。

以较小模型和16k上下文为首个建议配置，实际型号和调用预算须另行确认。需要32k时单列原因和实际改善，不能悄悄使用更大模型后说小窗口通过。材料超限本身也是确定结果，不通过即给出具体单元与缺项。

测试审阅纠错可用scripted Provider注入以下错误：status选择写反、订金/本次付款混义、SUM粒度错误、普通INDEX当FK。真实模型纠错能力还需另行实测；scripted测试只证明纠正稿进入产物，不证明模型会自主发现。

P1通过只代表受控材料上的语义链可行，不能证明自动选材。

## 5. P2：独立自动选材与跨Controller发现

从同一原始R4/R0重建独立实验批次：

1. 可使用全部技术导航和项目说明；不传P1结果、人工选材路径、正确字段、两份参考HTML或本页答案。
2. 调查范围可由用户指定普通业务问题，但不得提示目标Controller、表、字段或正确关系；本体类别、联系和指标由证据决定。执行上下文只拿原始R4/R0及通用配置，不含本页/人工走查/历史对话中的答案，评分只在运行后进行。
3. 模型提出具名材料请求，程序返回原文；保存读过、保留、移出、未命中、未读/超限范围。
4. 完成局部提取与审阅；由反向导航/字面搜索寻找其它Controller相关资料。
5. RELATE与原文REVIEW后输出小样；比较P1缺失/多出的定义，但不在执行中偷偷补入P1答案。

共同线索、具体目标、按题独立选择及有限查询已接通并通过直接测试；可能相关的6–8个入口不再机械变成必读Controller。P2i实际从41题选2题，第一题只读取4个完整方法；随后已读方法包引用用于反查时被当时的类别校验拒绝，未产生已审定义。类别合同已修正并零模型检查，但旧P2i仍不是成功运行。因此不能宣布自主聚焦或本体识别通过。原始P2/P2g/P2h/P2i结果均保留，旧版本决策不能冒充新版输入；新版类型化真实实验须另获具名授权。

为使“独立”可检查，启动前冻结中性scope、通用Prompt版本及原始R4/R0清单；scope不包含财务、Controller、字段或正确关系提示。负责驱动的程序只从这些输入组装请求，不读取本设计/评分页/旧模型稿件。运行后审计实际模型可见的首批SURVEY、全部search/read及EXTRACT/RELATE/REVIEW输入，检查没有人工插入P1清单或评分答案。模型自行从导航/原文读到相同业务词或键是允许的，不能用字符串禁词替代输入来源审计。评分人员另读评分资料，不能向运行中的选材任务发正确路径。负责启动的Agent即使读过本文，也不手动选择/补写P2材料。

P2须命中预先固定但**不暴露给模型**的评分目标：本次为财务明细billNumber→业务头id→财务明细billId→查询/条件欠款回写，或在运行前选定的等价难度目标。须逐项列标识转换、保存、读取、条件回写及R4/R0出处；发现任意更容易的跨Controller关系不能替代该项。若只发现共享表或同名字段，不通过。关系没有被发现时，报告具体导航、搜索、选读断点，不回头重建JDT/Activity，不先搭知识图谱平台。

第一轮设置有限请求上限：预检后按具名任务清单给实际H/B/L/K和允许总数。可以先设置总数24作为实验防失控上限，但它不是预计一定够用的调用量；超限则范围INCOMPLETE并报告尚未执行任务，是否追加须用户决定。不得把达到上限写成全仓完成。

## 6. 检查表：依据现有实现，不要求统一对象数量

| 项目 | 通过标准 | 明确失败例 |
| --- | --- | --- |
| 对象身份 | id主键与number业务查询键分开；未知唯一范围列明 | number普通索引被说成全局唯一/FK |
| 业务变体 | 同表不同用途保留条件；拆对象或角色方案可不同但机制准确 | 一表一个对象、一个Controller一个业务 |
| 采购关系 | linkApply、linkNumber、明细linkId及适用条件准确 | 强制所有业务依次请购→订单→入库；联系无键机制 |
| 默认/状态 | status为空才默认0；purchaseStatus初始化与用途不混 | 所有新增status均0；来源状态1/3写成0/3 |
| 金额 | 订金、本次付款、优惠后金额、最终欠款分别定义 | 统称应付金额；忽略付款符号/汇总绝对值位置 |
| 跨Controller | 财务明细billId可追到业务头id；读写/回写链和条件有原文 | 只凭共享表/字段名、日志方法批准业务关系 |
| 审核 | 当前状态、purchaseStatus拒绝和强审核库存例外保留 | 通用库存检查扩展到全部出库类型 |
| 指标粒度 | distinct头记录及Java分支、净值与过滤保留 | 按明细重复求头金额，采购使用零售绝对值规则 |
| NULL/失败 | 保留金额可NULL与实际无NULL保护的异常路径；只确认正常非空口径 | 自动NULL=0，或声明所有合法存储行均稳定返回数值 |
| 时间/权限 | 闭区间、实际期间、creator筛选与返回遮蔽/Controller分支保留 | 随意补时区/币种；筛选即任意GROUPING |
| 不确定性 | baseURL、PARTIAL SQL、未读、未知按实际内容保留 | 已有页面候选升格确定部署链 |
| 原文审阅 | 修正结果进入最终JSON/视图；被拒项不重新出现 | 最后润色把正确规则改错 |

准确对象数或业务名称不是通过条件。允许不同合理建模法；不允许关键标识、条件或口径错误。人工检查按具体输出与原文比较，不只按coverage闭合或JSON合法。

## 7. 测试与框架通用性

直接自动化测试用scripted Provider验证：

- R4/R0及排除版本、跨包短编号、已存上下文/完整正文不丢；
- 缺材料、UNIT_TOO_LARGE、未命中、动态限制及部分范围不伪造完成；
- OBJECT/ACTION/ANALYTIC输入及原文REVIEW实际收到哪些内容；
- SAME_OBJECT/ROLE_OR_VARIANT/BUSINESS_LINK及不合并处置，断引用拒绝；
- 指标filters/grain/维度用途及修正结果稳定保存；
- 没有WRITE、没有真实模型/JDT/SQL执行；旧分析reader/模型任务调用数为0；
- 正式化后CLI→Agent→存储→inspect/artifact的准确归属及重开。

本次新增直接验收还须覆盖：真实R4的`statementRefs`对象形状、空AST/无COLUMN节点仍保留未知、高扇出分页、线索不是业务关系、跨页短键和变体不串用；选8个候选而仅请求2个首批单元时，其余Controller不被自动读取；零正文导航起步、有限查询、必要原文门禁及局部超限保存。断点、消费链和具体实现面见[选材设计§8](evidence-navigation-and-selection.md#8-待改动面验证与退出条件)。

框架防过拟合：

1. 通用Prompt/Java中不得出现jshERP类名、业务状态值或采购阶段答案；它们只存在fixture/验收材料。
2. 准备最小自有非ERP fixture，例如工单/人员分配和处理时长：检验系统未知/非ERP、不同身份、零指标或不完整定义也合法。
3. 该fixture只能检验合同通用性，不能代替第二个真实客户系统的模型验收。不宣称测试一个ERP就已保证所有框架。
4. 模型变更保存实际绑定；同一问题不能跨模型结果默默复用。

优先跑新增和直接覆盖测试；不运行无关整仓套件，不重新生成现有业务结果。历史PoC自主识别未通过不再阻止已批准的材料框架与正式CLI接线；但仍不能宣称自主发现成功或启动全仓本体。不设计旧内容迁移或兼容回归矩阵。

## 9. 失败定位与收口

按五种性质报告，不统一说“模型不行”：

1. **来源/结构问题：**资料损坏、错版本、引用不合法；先修读取/合同，零模型复核。
2. **材料选择问题：**证据存在但没读到；列导航/搜索/请求断点，只修改必要提示/投影。
3. **容量问题：**完整必要单元不容纳；列实际输入与余量，缩小问题或明确更大配置，不静默摘要。
4. **推理/审阅问题：**读到了仍把条件/粒度/身份弄错；列实际原文、候选、审阅结果，不能用字段合法放行。
5. **源证据不足：**没有状态定义、运行地址、时区/币种等；保持未知，不造证据补齐。

最终报告分开给P0、P1、P2、正式CLI贯穿状态，实际请求/复用/等待/存储时间及人工发现错误。P1成功P2失败时不能宣布自主识别可行；技术成功语义失败时不扩大到全仓。

正式化后若声称“正式路径自主识别通过”，最终CLI→Agent→store路径还须从原始R4/R0执行一次独立P2、审计实际输入并核查同一隐藏目标。薄驱动P2通过不能自动转成正式路径通过。若未获该实际预算，仅报告正式技术贯穿/受控材料模式通过，保留自主识别未验收状态。

小样通过后再由用户决定是否正式化/扩大；本设计没有自动全仓模型许可。P1已证明在人工提供相关材料时可生成五项已审定义，仍待人工接受；P2尚未证明自主聚焦及跨Controller隐藏目标通过。不能用P1或字段/保存测试替代P2。

## 10. 当前设计核验与仍待验收

已核对当前Corpus→决策→阅读→提取的真实读写链和P2保存输入；已读方法反查已通过零模型回放，仍需新版真实模型验收。不是要求重新取证。DDL工具的有限走查结果仍不算自动DDL能力完成。

首版模型执行位置已确认Java Provider，Skill编排和报告；新版薄合同和49项直接测试完成。P2g暴露的汇总容量问题已经通过先比较问题、选定后按题给导航解决；P2i暴露的包内已读JAVA_METHOD与METHOD_USES查询键类别问题，已完成最小合同修正、直接测试及保存响应零模型检查。新增类型化小范围实验已完成scripted贯穿，真实普通问题实验及G1后正式四命令仍未完成。新增模型范围不能由剩余调用上限自动取得授权。
