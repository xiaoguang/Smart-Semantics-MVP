## 提交前审查发现、尚未完成验证的缺口

1. 大包某个 slice 的 REVIEW 失败后，显式新批次原本会重新调用阅读选材，而不是先重开已保存的完整阅读计划；可能浪费调用并改变 slice 身份，妨碍只续接失败阶段。
2. 一个必需 slice 未读完时，其他 slice 的成功可能让入口表现为普通 `ANALYZED_WITH_GAPS`，批次完成判断、手动重试范围和 Step07 准入未把它识别为未完成。
3. 后一个 slice 失败时，前一个已审 slice 留在私有记录中，却没有进入公开 M11 的部分成功集合。
4. Codex 子进程将多数非上下文容量错误归为 `UNKNOWN`，限流/暂时容量无法按配置重试；认证、配置或额度耗尽也无法使同服务后续排队任务及时停止。
5. 阅读决策只校验顶层字段就保存 `SUCCESS`，具体未知引用、重复 slice 等错误随后才出现，绕过了配置的响应重试。
