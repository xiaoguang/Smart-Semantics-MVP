### 本地运行接线要求

JDT 的受控项目必须接收本次配置明确列出的已有依赖 JAR，而不是在正式运行器中固定传空 classpath。依赖只用于 JDT 读取类型，不执行其中的应用代码、不触发客户构建、不联网解析依赖；沿用 `VerifiedJavaProject` 对依赖内容和项目指纹的校验。工具清单保存这些 JAR 的名称与 SHA。公共分析请求仍只引用注册来源；本地路径仅属于启动配置。

这是已有能力的接线修正，不增加注解推断规则或新的解析器。修正前后必须对比整仓候选入口和实际入口数量；仅有少量入口被识别时不得调用模型并宣称整仓分析。

实际 preflight 已发现报告 Schema 将同一批来源编号展开 18 次；即便前一轮只有两个材料、62 个来源，也达到 1,134 个枚举值，超过官方 Structured Outputs 的 1,000 项限制。按第八步详细设计做最小传输修正：段落 ref 使用受限字符串，完整 allowlist 留在输入与 Java 接收校验中，九章编号/标题枚举不变。不删来源，不变业务正文合同，不新增 Schema 转换框架。修正前不启动报告请求。

整仓导航首次走到保存时暴露入口投影冲突：保存器按物理callKey比较完整CallSite，但展开结果由每个入口自身的遍历决定。按[导航索引保存合同](../modules/java-code-engines/contracts-and-configuration.md#5-保存格式位置与复用)局部升级索引v2：全仓共享方法正文，调用投影按入口保存；源码字段仍校验一致。先用双入口公开发布/重开回归证明完整与未展开结果均不丢失，再执行选定四入口。只改publisher、reader与直接版本注册，不改JDT解析/导航算法，不启动恢复或性能子系统。失败运行与日志保留，不能把尚未落盘的内存结果称为可复用产物。
