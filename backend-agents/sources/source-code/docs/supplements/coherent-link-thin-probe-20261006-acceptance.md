# 联合联系识别最小改进：薄实验验收

## 结论

两例完成一次提取、一次审阅，共四次 Luna/high 请求，均形成端点闭合的对象—联系结果和可查看的局部图。**支持采用“精确结构诊断、围绕一个锚点提交完整原文、短标签局部图”方向；不等于小窗口、全采购链自主发现或正式 CLI 改造已经通过。**

实验位于 `.workspace/coherent-link-thin-probe-20261006/`，没有修改生产 Java、Provider、Prompt、Schema 或旧 MD。使用现有 Provider、原有 LINK candidate/review v1 Schema，以及框架自带 Mermaid 11.12.0。没有新增解析器、模型路由、布局引擎或自动重试。

## 精确诊断

旧调拨审阅稿只定义`warehouse`，却将关系端点写成`depotItem.depotId`与`depotItem.anotherDepotId`。新诊断准确返回：

```text
$.links[0].fromKey: actual=depotItem.depotId; defined=[warehouse]
$.links[0].toKey: actual=depotItem.anotherDepotId; defined=[warehouse]
```

程序没有替模型猜“正确对象”。离线测试同时证明合法同类型自关系不会因两端相同而被拒绝。本次真实提取没有再次产生这两个坏端点，因此**只证明诊断可以精确定位、两例新结果通过引用校验；没有隔离证明诊断本身是模型改善的唯一原因。**

## 实际模型结果与语义核验

### 采购

两对象：采购入库单、采购订单。一联系：采购入库单关联采购订单，最终模型标为`INFERRED`。

模型实际引用S12的选单操作、S13的选择回调，以及S5的保存方法。原文包含选“采购订单”、将`linkNumber`放入当前表单、后端读取`getLinkNumber()`并调用相关状态辅助方法。这些已入模，不是人工补出的模型答案。

仍有模型质量问题：最终审阅删掉了未知项，`unresolved=[]`，没有充分披露未读状态辅助实现等限制。引用校验通过不证明状态计算、库存效果或物理外键已经确认。材料自身的`scopeNotice`、逐调用冲突和未读清单仍保存；模型删未知不能改变它们。

这次只测试来源订单号联系。**没有新增证明“请购→订单→入库”全链自动选材。**模型没有输出请购单，不能补画。

### 调拨

两对象：调拨明细、仓库。两联系：明细关联仓库端点、明细关联另一个仓库端点，均标`INFERRED`。两个字段分别表达到同一种对象的用途，不被错误当成两个未定义对象编号。

首稿曾把端点称为调出/调入；审阅依据同一S39改为未命名的两个端点，保留方向、仓库身份和基数未知。源码所给依据是读取两个标识、检查二者不同、赋值到明细；不据此宣布库存增减规则已确认。
