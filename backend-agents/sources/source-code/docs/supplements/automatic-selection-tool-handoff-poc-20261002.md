## 本轮调整合同

1. SEARCH只做区分大小写的连续子串匹配。Prompt、输入工具说明和Schema使用同一语义；不增加分词、语义搜索或业务词典。
2. 每个模型请求独立，不能依赖前一请求的对话记忆。新增有界ENTRY_LIST分页查询；后续输入保留当前材料或查询涉及的入口卡、列说明和状态解释。无需每轮发送339张卡。**实测边界：这只支持显式恢复入口，尚未持续保留已经选中但未阅读的另一端导航；财务题因此出现查询端导航从后续请求消失的问题。**
3. 完整方法正文不变；方法所属全部调用用紧凑表提供位置、接收者、实参、控制关系、解析状态及候选目标。声明重复只写一次。完整技术观察和身份映射留在程序侧，可通过合法详情短引用读回。矛盾、未知、外部及候选状态默认可见，不以压缩名义将其变成确定调用。
4. 查询候选成本按实际投影计量。方法中附带的实现目标导航只报`navigationBytes`并显式写`fullReadProjectionBytes=UNKNOWN_UNTIL_READ`，不递归展开全部目标来估算，也不将导航大小冒充完整阅读成本。被查询或READ时执行实际容量检查。一次READ失败要说明候选单元、独立请求大小、累计请求大小和70000字节上限；若单元自身已超限，封套尚未构造的大小字段为0，不能当作独立包实际为0。独立也超限时不得继续给“移出材料后再读”选项；只有累计超限才提供该选择。
5. 默认容量仍为70000 UTF-8输入字节、160000封套字节含20000输出余量，每轮最多2动作、2查询页和50结果。字节通过不等于任意token窗口兼容。
6. 反查只提供实际可执行的来源类型和值：方法查使用者、XML语句查使用者、表查询使用该单元明确显示的`relatedTableNames`导航清单。这份清单来自已有Corpus线索，不增加SQL解析或业务判断。反查以当前请求已读资料为准，模型可以查询后将正文移出下一轮；不能因为先执行移出就将本次合法来源判成未知。已移出的完整资料以后若再次出现在合法导航中，允许模型显式重新读取；不自动读取、不重派模型请求，正文仍按引用去重。当前已保留正文不提供重复READ选项。
7. 同一响应重复READ同一个合法引用时，完整正文只读取一次，重复动作及各自用途留在回执；不会因此发送额外模型请求。已保存的原始响应不修改。本次接续只重放当前实验已派发的三份实际输入/响应，并逐份核对输入相同；不重发前三次、不使用旧实验答案，最多继续剩余13次，总新增额度仍为16次。
8. 两个问题分别保存结果。后来发生的具名响应/动作错误使本题INCOMPLETE，但未开始的另一题仍可在原授权范围执行；不重试失败题。来源、存储、Provider及前缀一致性故障仍终止运行。

70000是继承自此前PoC的实验配置值；当前驱动还校验它必须恰好为此值。这不是JDT、JSON、Provider或某个模型的已验证技术上限，没有找到恰好选择70000的实测校准依据。本次超限表示程序拒绝派发，不表示模型已经失败，也不能单凭此值认定框架路线不可行。正式配置不得把该数值包装成普遍的小上下文标准；本实验仅保持原阈值作前后对照，尚未改变它。
