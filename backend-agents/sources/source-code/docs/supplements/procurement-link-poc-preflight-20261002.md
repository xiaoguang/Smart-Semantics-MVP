## 2. 为什么不能把入口 JSON 整份交给模型

原 R4 新增单据入口文件为 3,530,376 字节。以下三份完整方法正文已经包含新增单据及明细保存的主要实现，合计 33,787 字节：

| 实际 R4 单元 | 完整正文 UTF-8 字节 | 本次用途 |
| --- | ---: | --- |
| `DepotHeadController.addDepotHeadAndDetail`，606–621 行 | 630 | 入口如何进入保存实现 |
| `DepotHeadService.addDepotHeadAndDetail`，1204–1312 行 | 6,572 | 主表、关联值、订金/付款及明细保存调用 |
| `DepotItemService.saveDetials`，380–738 行 | 26,585 | 来源明细、数量检查、库存调用及来源状态回写调用 |

两者不是同一种数据：几 MB 的入口文件还包含其它方法、调用观察、重复声明、来源及运行身份、XML 资源等。上述 33,787 字节**也不是充分阅读包大小**，尚需具体联系所需的页面、被调用实现、XML 依赖和限制；不能用此数字证明小上下文兼容。

按完整单元人工列出的请购→订单、订单→入库原文候选量约 43.7 KB、44.9 KB。这是只计原文的初步估算，不是实际序列化请求、不含 Prompt/Schema/实际提取稿及输出余量，也未证明这些单元足够。后续必须逐阶段测量，不能将估算写成容量通过。

## 3. 选入、移出与必要的补充

投影规则受[backlog 第28项硬约束](implementation-lessons-and-followups.md#28-兼顾较弱模型的业务联系核验设计硬约束)约束。保存完整证据不等于全部进入模型。

| 处理 | 内容 | 边界 |
| --- | --- | --- |
| 留在程序侧 | 长 ID、摘要、receipt、绝对运行路径、重复目标声明、与本次判断无关的调用明细 | 保留可逆短号映射和移出理由，不让模型抄写身份 |
| 整合后进入模型 | 一个问题、必要完整原文、两端用途、必要实参/形参、条件、分支、金额/数量过滤及限制 | 正文去重不能合并不同页面/入口用途；不附入全部所属调用 |
| 明确缺失 | 未取得的必要实现、未确认调用边、地址条件及动态 SQL 限制 | 不能因压缩而消失，更不能变成确定关联 |
| 实验补充 | 同源前端实验单元；确有必要时读取同 R0 的具名完整实现 | 独立标记来源与取得方式，不安装为正式 R4，不冒称自主找到 |

### 正式 R4 中确实缺少的实现

对当前全部 339 份 `entry-*.json` 的 `java.methods` 核对，没有完整正文的具名方法包括：

- `getBillStatusByParam`、`changeBillStatus`、`changeBillPurchaseStatus`；
- `updateCurrentStockFun`、`getStockByParam`；
- `updateLastDepositByNumber`。

新增入口的部分对应调用实际保存为 `NAVIGATION_CONFLICT`、`targets=[]`，说明程序没有沿这些调用取得正文；不是压缩导致的缺失。同 R0 原文有上述实现，但其存在不能把 R4 中未确认的边自动升级为确定绑定。没有这些实现就不能完整核对状态计算、库存重算和剩余订金写回。

### 已有原文但未形成所选结构化单元

数量汇总查询 `getLinkBillDetailMaterialSum`、`getBatchBillDetailMaterialSum` 已在 R4 的 `DepotItemMapperEx.xml` 完整资源原文中保存。部分订金汇总查询也在其它入口所保留的 `DepotHeadMapperEx.xml` 中。它们未必出现在当前选中的 `persistence.statements` 数组，不能因此说 SQL 原文没有取证。后续可复用已有安全 XML 读取能力取得完整元素及其依赖，不重新运行 SQL 分析器。

财务保存入口没有包含某个欠款回写方法，不等于全仓没有：`updateLastDebtByBillId` 正文在现有批量欠款入口的 R4 中。需要反查整个固定证据集，而非只查看起始入口。

## 4. 候选核验任务

以下是本次具名 POC 的人工核验问题，不作为通用 Prompt 的业务答案、行业规则或 Java 语义判断。每个问题单独提取和对同一原文审阅，不把六项源码硬塞进一个请求。

| 小联系 | 两端需要一起阅读什么 | 人工核查重点 |
| --- | --- | --- |
| 请购明细→采购订单 | 订单页面完整选择回调、保存实现、后端主/明细保存、关联数量与状态实现/XML | 来源明细身份怎样产生与保存；关联请购值；分批数量及回写对象 |
| 采购订单明细→采购入库 | 入库页面完整选择回调、保存实现、后端主/明细保存、关联数量与状态实现/XML | 剩余数量、来源订单、状态规则；不能把其它订单业务分支套进采购 |
| 采购入库记录→库存口径 | 明细保存、审核实现、库存重算实现和汇总 XML | 建单、审核及配置的不同条件；不能把一次调用直接称为物理收货 |
| 订金/本次付款→剩余订金或欠款 | 主表保存、订金汇总/回写、欠款计算及实际页面字段用法 | 金额含义、累计过滤、创建时提交值与后端计算的区别 |
| 财务明细→业务单据 | 财务主/明细保存、按单号查业务主表、明细插入 XML、反查查询 | 单号怎样取得业务 ID，ID 怎样写入并被查询；失败处理 |
| 财务金额汇总→最终欠款 | 财务明细保存、业务欠款计算、财务汇总 SQL、欠款回写实现/XML | 汇总粒度、删除过滤、先汇总再取绝对值、非零/非空条件 |

尚不能确认的范围包括实际部署地址、某次请求或数据库写入是否成功、单号的全局唯一性、所有配置组合以及银行付款或会计记账效果。实验结果必须保留这些未知，不补写成完整运行时闭环。
