# 跨对象业务过程重建：补充设计入口

状态：**2026-09-16 已批准，新增接线及直接测试通过，真实实验和完整验收进行中。** 冻结查询、完整阅读流程、CLI及canonical发布的直接测试已通过；样本成功、失败和仍待验证范围分别记录，不等同全仓验收。具体事实见[实施与验收记录](delivery.md)。本轮不重新生成 JDT、Activity 或九章，历史结果只读。

## 1. 要得到什么

从已有材料说明系统支持哪些业务，每种业务怎样开始、经历什么步骤与分支、满足什么具体条件、改变什么对象、怎样结束，以及哪些联系仍不能确认。主要出口继续是 `business-processes.md`，附结构化目录、覆盖和来源。不是把接口或 CRUD 分类换成业务标题。

本补充替代活跃设计中的两条旧限制：

1. 阅读范围不再限于当前候选 Activity 已引用的 M10 片段，可以在**同一冻结来源**内选取其他已审 Activity、M10 原文和冻结文本。
2. 必要的选中原文在过程 **DRAFT 之前**到位；不再等过程已经成形后才给 REVIEW 补关键实现。

它不替换八步主线、两级并发、公共 Agent、来源信任或既有五文件发布；各模块文档已同步这两项约定。`more-findings.md` 保留原文，作为本设计的讨论背景，不把其余增强一并纳入。

真实样本后已另获两项有限批准：CHECK 输入只省略任务不用的 statementDirectory、已完整提供 Activity 的重复导航卡及未读导航卡的 terms，保留全部完整 Activity/源码、全仓召回能力和原全局选择/最终 DRAFT/REVIEW；租户已完成 raw REVIEW 只修正一个经核对的错误类型用法引用，零新增模型调用，旧 raw/FAILED run 不变，新派生 pair 附不可覆盖清单和可复用的来源标记。精确约束见[模块设计 §3、§7](module-design.md)及[直接验收](acceptance.md)，不是新的压缩、自动修复或恢复框架；实施状态以交付记录为准。

修改前的准确现状是：**完整 Activity 和少量源码预览先进入 DRAFT，选中的完整源码随后进入 REVIEW。** 不是“现在只有摘要”，也不是“326 个活动需要重建”。本轮复用底层已有 `VerifiedSourceTextReader`，新增 Step07 冻结查询和取材接线；查询 helper 已实现，尚不能据此宣称模型实际收到完整包。

这些可读 ID 用于定位已有记录；实现必须从现有保存记录解析完整 checkpoint/任务引用，不手写 receipt、不凭 ID 猜文件内容。旧目录 REVIEW 的处置数组不是唯一分母：沿用现有完整 DRAFT 处置及已审成员关系的规范化，不把重复数组行数当覆盖数。

## 3. 新的接力

```text
重开旧目录 + 全部已审 Activity + 同源冻结文本
  → 一次全局选材：候选修正 + 首批阅读清单
  → Java 取回完整 Activity 和选中的原文
  → 每候选一次模型阅读检查：补读清单可为空
  → Java 执行非空补读清单；不再启动第三次选材
  → 自包含 ProcessReadingPacket
  → 每候选一次 PROCESS_DRAFT + 一次完整 PROCESS_REVIEW
  → 现有仓库归并
  → 现有五文件发布
```

**模型决定还缺什么，Java 负责取回。** 可选的是实际补读，不是由 Java 决定是否需要模型阅读检查。每个进入重建的候选都有一次检查调用；返回空清单即直接组包，仍有未知项则随包保存。次数用完不等于材料充分、业务完整。

这条路线有新模型工作：选材、阅读检查、过程解释及归并。省掉的是重新扫描、重新生成 Activity 和重新跑原目录分片/合并，不是省掉业务理解本身。新仓库没有旧目录时，保留原来的首次目录发现能力。

## 4. 谁做什么

| Java 的确定性工作 | 模型的业务工作 |
| --- | --- |
| 打开旧产物，按 ID 和冻结文本定位取材 | 选择值得共同阅读的活动和原文 |
| 字面量搜索、行范围/文件读取、去重 | 修正候选、理解业务对象交接 |
| 校验真实 ID、已读引用、来源范围及容量 | 解释步骤、具体条件、规则和结果 |
| 保留原内容和处置，稳定保存及渲染 | 区分可选、回退、支撑、推断和未知 |

不增加行业词典、SQL 执行器、Vue 编译器、对象交接证明图、语义向量库或中文蕴含检查。来源能定位即可；缺链接可留空，不为此追加模型或取证任务。
