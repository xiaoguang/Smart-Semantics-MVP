# 自动选材与三阶段业务解释：最小研究实验

本次仅验证用户2026-09-16批准的两个假设：模型能否根据全仓信息提出业务方向，自动取齐一个业务过程的关键材料；DRAFT→专门规则REVIEW→正文写作能否达到已接受采购样例的阅读水平。

这是一次研究实验，不接入生产。使用现有326条已审Activity和固定提交`8c30ce7861570458920175e200bb2a6442713580`的冻结文本。不重新扫描、重建Activity或续跑全仓。

## 执行范围

最多五次Luna/high、现有ChatGPT登录请求：

1. 全部Activity导航卡、全部冻结文本文件目录及根README进入选材；模型判断系统特征、提出可验证的业务假设并选择一个业务方向及首批读请求。
2. 程序读取模型指定Activity和原文；一次阅读检查形成最终清单后封包。真实首批请求包含约91万字节源码，超过本次小包需要：完整原文仍保存，大文件在CHECK仅展示明确标记的真实预览、声明行及实际搜索命中，由模型收窄到完整相关方法/映射范围。不是程序人工指定业务实现。
3. DRAFT从实际阅读包形成完整业务事实与流程底稿。选材实测仍过宽，两个假设独立验证：本次用`--fixed-packet`，只承接上次人工基准的原始材料，重新DRAFT；不读取上次任何模型文章，也不承接自动选材的业务结论。
4. 规则REVIEW从同一原文及完整实际DRAFT核对并给出完整修订底稿，不润色成文章。
5. 正文写作仅从实际核对底稿写业务说明。

没有自动重试或另一次成稿。模型失败、输出无法解析或核心材料未取得时保留结果并记录结论。请求不在冻结文本目录的文件时记录未取得，不读取任何外部文件，交给唯一CHECK对照真实目录处理；来源字节损坏仍停止。材料不足不以人工补答案掩盖。具体请求和原始结果保存在忽略的独立工作区。

```bash
node research/business-material-and-three-stage-spike/spike.mjs prepare
node research/business-material-and-three-stage-spike/spike.mjs select
node research/business-material-and-three-stage-spike/spike.mjs check
node research/business-material-and-three-stage-spike/spike.mjs draft --fixed-packet
node research/business-material-and-three-stage-spike/spike.mjs rule-review
node research/business-material-and-three-stage-spike/spike.mjs write
```

选材和阅读检查使用研究JSON约定，仅包含材料选择，不受旧生产协议约束。程序只读取冻结文件、做字面量搜索和保存，不解释行业关系。

实测阅读检查的read请求覆盖77个文件，计入search实际片段后共80个文件、101个片段、源码856790字节及32条Activity；请求更具体并补出付款实现，但没有得到小而聚焦的输入。该自动包完整保存为`automatic-reading-packet.json`，不送入后续三阶段，以免材料范围变化干扰三阶段对照。本次不是自动选材到成稿的端到端成功证明。

## 验收

- 指令不预置行业名称、目标链、正确成员、文件路径或阶段答案。首个请求不读取上次实验的选材清单或文章。
- 模型提出的业务假设可以撤回；实际说明必须来自读取到的Activity/源码。
- 检查选材能否取得页面业务含义、主实现和相关数量、状态、金额处理；没有取得的内容明确记录。
- 检查输出能否让读者复述如何办理，并保留主要对象交接、可选/分批路径、具体条件和结果。
- 采用已接受文章的可读性作为基线；一般措辞问题列质量事项，不扩建验证系统。重要事实错误单独列明，不能因读得顺而隐去。
- 本次只验证一个样本；结果不宣称全仓或跨领域稳定性。

预估准备与直接检查20–40分钟，模型五次约15–30分钟，按实际记录校准。旧材料、文章、回执和受保护文档保持原样。

## 已完成的实验结论

五次请求已经完成，模型累计18分34秒；后三阶段13分31秒。系统类型推理和相关材料召回成立，但自动包仍偏宽、部分基准页面未选择。后三阶段能生成完整业务正文，却在写作中将已审核来源单误写成未审核，并混淆多账户金额的业务名称；重要规则保持本次未通过。没有追加修补请求，不宣布自动端到端成功。

真实原文、选材、核对底稿和逐项结论见[实验报告](../../.workspace/automatic-material-three-stage-spike-20260916/report.md)。下一步应分别处理选材收窄和写作承接已核对业务表述，仍无需重跑JDT、重建Activity或扩建证据系统。这个改进方向尚未再次验证，不能当作已通过的生产设计。
