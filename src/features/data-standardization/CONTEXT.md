# 管伊佳数据标准化工作台领域上下文

## 目的

这个目录承载“运行中的来源资料治理”投影，而不是来源采集器、LLM 或正式模型发布器。
调用方只操作当前运行、来源文档、即时来源差异决定和可带缺口定版的交付；所有阅读内容
来自已提交的冻结资源。

## 核心概念

| 名称 | 含义 | 不等同于 |
| --- | --- | --- |
| 正式来源快照 | 正式运行的 `sourceId + snapshotId` 身份 | 浏览器缓存或连接配置 |
| 内容快照 | `guanyijia-demo-content-v6-20260826` 的人类阅读材料 | 正式 Claim、Assertion、Conflict 或 V1 |
| 运行绑定 | 一个 `runId` 对五项正式身份和内容 SHA 的不可变选择 | 可由刷新静默更新的“最新内容” |
| 来源审阅投影 | 单源的“审阅事项／审阅结论／标准化文档”三页签及经验证的剧本化文字修订 | 来源采集器、任意源码浏览器或自由编辑器 |
| 本来源建议 | 用户保留或采用的当前来源剧本化建议 | 来源差异或对来源原文的自由编辑 |
| 来源差异与比较 | 已准入运行资料形成的正式差异或尚待前提的比较项 | 当前文档专属的一次性提醒 |
| 即时正式差异 | 已具备决定前提、已写入 `introducedConflictIds` 的来源差异 | 可延后到流程末尾的待办 |
| 等待更多来源 | 已识别、但尚未具备正式决定前提的比较项 | 已可保存的正式差异 |
| 待补充资料 | 材料不足的逐项业务记录；用户语言，不显示内部 `GAP` | 阻断继续读取来源的错误 |
| 已处理事项 | 已保存、可审计和回看的建议或正式差异决定 | 会在切换来源后消失的 toast |
| 来源过程 | 读取、分析、组织、审阅四个真实来源处理阶段 | 用假定时器模拟的进度条 |
| 合并结果预览 | 五份完整审阅后 V6 文档和决定形成的同一份三页签文档 | 已持久化交付物、草稿或另一份内容 |
| 作者定版 | 作者确认完整标准化文档并冻结交付物 | 正式 V2 发布或独立审核 |
| 建模资格 | `ELIGIBLE`、`EXCLUDED_GAP`、`EXCLUDED_UNCERTAIN` 的结构化筛选结果 | 是否写入完整 Markdown |

## 读取合同

`DemoContentReview` 是 sidecar 的唯一 seam：`bindRun()` 创建绑定，`readSource()` 返回
来源纯度投影。工作台不得读取 sidecar 的目录、Git 树或生成脚本，且不得回退到旧模板正文。
绑定、来源身份、内容 SHA、Markdown、摘录或 trace 不一致时，受影响来源必须 fail closed。

来源始终按数据库、代码仓库、业务文档、ERP制度、术语图顺序准入。只有参与来源已准入，
跨来源比较才可展示；MySQL 文档不得提前出现 GitHub、业务文档、制度或术语图内容。

## 展示和动作合同

每个来源的标签顺序固定为“审阅事项／审阅结论／标准化文档”，默认打开“审阅事项”。
审阅事项分为待确认事项、待补充资料和已处理事项三个独立分组：待确认事项内的本来源建议
与来源差异与比较必须是两个同级 Box；前提不足的比较项显示“等待更多来源”；已保存建议和
正式差异决定进入已处理事项且永不因切换来源而隐藏。资料缺口逐项可读、不显示内部 `GAP`，
也不阻塞来源推进。

`introducedConflictIds` 是正式差异的唯一权威。任何已引入 ID 必须且只能在所属来源的
未决来源差异卡或已处理事项中出现一次，并同时作为右侧来源“审阅”阶段的子节点和时间线
节点。缺少候选适配器时显示完整性错误，阻止写操作、完成来源和生成结果；不得静默隐藏。
正式差异在它成立时立即内联展开。建议尚未保存时，差异可见但说明先核对建议；建议保存后，
第一项正式差异拥有唯一 Primary“保存当前决定”。未保存正式差异时命令层拒绝完成来源、
开始下一来源和生成结果。保存后，事项卡和右侧节点均为绿色。

来源主线是自动的：用户完成当前来源审阅后，来源自动收起并开始下一来源；上一份文档保持
只读可见，直到下一份经过读取、分析和组织而进入 `DOCUMENT_READY` 后自动打开。历史来源
被用户主动打开时，新的就绪来源只提示，不抢走阅读位置。右侧来源过程的未开始为灰色，当前
为蓝色，完成为绿色，失败／完整性／SHA 错误为红色。来源过程必须反映真实处理边界，不能用
假定时器伪造。

标准化文档是当前 Revision 的只读 V6 阅读投影，保持九章内容、证据、DDL、源码和按需展开。
阅读版将连续 `GAP n` 只读投影成逐项“待补充资料”；Markdown 源文与复制结果保持冻结字节。
经保存的剧本化修改由 `projectSourceReviewRevision()` 覆盖到相同 Claim 的可见投影，绝不改写
冻结来源字节或 trace。编辑建议时，用户始终看到即时本地预览；异步 SHA 校验只决定“保存修改”
是否可用，不再要求点击“预览修改”。

审阅结论展示可阅读的业务结论和默认展开的对象目录，不直接承载未决差异。对象目录保留对象
计数、来源动作和文档锚点；SQL／DDL 只在查看来源依据后展开。标题与正文应先表达业务意义，
准确表名、字段、过程名和原始 SQL／DDL 留在可展开证据中。内部 ID、SHA、摘要、内部枚举和
原始 JSON 只属于技术详情。

工作台主审阅区是唯一纵向滚动拥有者；助手输入在其后的第二行，不覆盖正文。全屏来源文档以
这两行共同组成唯一 modal 根。页头、来源文档和移动层任一时刻最多一个工作流 Primary。

## 定版与保护

五份来源完成且所有正式差异均保存后，工作台自动进入同一份完整合并文档的三页签预览。三个
页签均绑定 `runId + sourceManifest + reviewedSourceManifest + decisionManifest + changeManifest
+ previewSha256`，且都能呈现完整九章、五来源正文：审阅事项强调补充资料和已处理决定，
审阅结论强调结论、对象目录和来源，标准化文档提供 GitHub Light 阅读版、Markdown 源文和复制。

最终人类 Markdown 来自五份用户实际审阅的完整 V6 文档及已保存 Revision／决定；正式结构化
文档仍用于建模资格和零变化校验，但不能替代阅读正文。合并顺序固定为九章、每章数据库、
GitHub、业务说明、ERP制度、术语图；不做语义去重、摘要或省略。用户修改在阅读版标为绿色，
可展开 GitHub 式红删绿增差异；复制 Markdown 不含展示标签或删除文本。

结果唯一 Primary“确认并定版”串行执行预览 SHA 重验、生成交付物、`mergedDocumentRef` 一致性
校验和作者定版。生成后定版失败时，保留同一结果并提供“继续定版”，不得重新生成。已登记的
缺口或无法确定项保持在 Markdown 中，并被结构化排除出 AI 建模候选；它们本身不阻止定版。

定版后“前往 AI 建模”只交接 `ELIGIBLE` 结论；`EXCLUDED_GAP` 与 `EXCLUDED_UNCERTAIN`
继续可读但不生成实体、关系、规则或指标候选。历史来源、历史决定和历史结果均只读。多标签
并发正确性不在本故事扩展，既有 Revision/CAS 继续保护写操作。

此过程不修改管伊佳 V1、Catalog、黄金摘要、对象计数或零售流程。
