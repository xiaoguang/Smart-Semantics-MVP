# 管伊佳数据标准化工作台领域上下文

## 目的

这个目录承载“运行中的来源资料治理”投影，而不是来源采集器、LLM 或正式模型发布器。调用方只操作当前运行、
来源文档、差异决定和可带缺口定版的交付；所有阅读内容来自已提交的冻结资源。

## 核心概念

| 名称 | 含义 | 不等同于 |
| --- | --- | --- |
| 正式来源快照 | 正式运行的 `sourceId + snapshotId` 身份 | 浏览器缓存或连接配置 |
| 内容快照 | `guanyijia-demo-content-v6-20260826` 的人类阅读材料；V1 至 V5 仍保留为历史快照 | 正式 Claim、Assertion、Conflict 或 V1 |
| 运行绑定 | 一个 `runId` 对五项正式身份和内容 SHA 的不可变选择 | 可由刷新静默更新的“最新内容” |
| 来源审阅投影 | 单源的“审阅事项／审阅结论／标准化文档”三页签、结论内按需展开的全部来源材料，以及经验证的剧本化文字修订 | 跨来源结论、任意源码浏览器或自由编辑器 |
| 本次读取发现 | 已准入来源之间的互补、差异、不同版本记录不一致或资料缺口 | 单源文档内容 |
| 治理决定 | 用户选择保留、采用新来源或登记缺口；内部兼容策略与审计摘要由系统生成 | 审批意见或用户填写的技术理由 |
| 作者定版 | 作者确认完整标准化文档并冻结交付物；已登记缺口是合法结果 | 正式 V2 发布或独立审核 |
| 建模资格 | `ELIGIBLE`、`EXCLUDED_GAP`、`EXCLUDED_UNCERTAIN` 的结构化筛选结果 | 是否写入完整 Markdown |

## 读取合同

`DemoContentReview` 是 sidecar 的唯一 seam：`bindRun()` 创建绑定，`readSource()` 返回来源纯度投影。工作台不得读取
sidecar 的目录、Git 树或生成脚本，且不得回退到旧模板正文。绑定、来源身份、内容 SHA、Markdown、摘录或 trace
不一致时，受影响来源必须 fail closed 并阻止完成审阅。

来源资料始终按数据库、代码仓库、业务文档、ERP制度、术语图的顺序准入。只有参与来源都已准入时，
“本次读取发现”才能展示关系；MySQL 文档不得提前出现 GitHub、业务文档、制度或术语图内容。

## 展示和动作合同

每个来源的标签顺序固定为“审阅事项／审阅结论／标准化文档”，默认打开“审阅事项”。“审阅事项”分为待处理的
剧本化或正式事项、资料缺口和已完成决定三个独立分组；已保存的决定会移入已完成分组而不会消失。资料缺口逐项可读，
不显示内部 `GAP` 字样，也不阻塞读取下一来源或继续审阅。“审阅结论”只展示可阅读的业务结论，并在互斥的核心结论与
对象目录集合之间切换；对象目录保留对象计数、来源动作和文档锚点，且默认展开。“标准化文档”是当前 revision 的只读
V6 阅读投影，保持九章内容及证据、DDL、源码的按需展开行为。每条结论内的“查看来源依据”会原位展开全部材料、位置和
支持的结论；“查看文档段落”会跳转到唯一锚点，并提供返回原结论的入口。底层仍校验
“来源材料 → 审阅结论 → Markdown 段落”的完整链路，但不为材料制造独立的阅读区。已审阅的来源重新打开时仍保留为
可读的只读内容，主要延续动作是“审阅下一个来源”。
Markdown 文档的阅读版只调整页签内部的阅读排版：章节导航位于正文上方并按容器宽度换列，正文使用可用宽度；数据库对象可在
对应条目内按需展开同一份已保存的字段结构和原始 DDL。该阅读器不改变工作台、右栏、流程、助手或来源审阅路径。
页头仅保留一个下一步动作：未核对时为“核对 N 项建议”，全部核对后为“完成{来源}审阅”；已审阅来源重新打开时为“审阅下一个来源”。

工作台主审阅区是唯一的纵向滚动拥有者；审阅助手输入区位于其后的第二行，既不固定也不覆盖正文。全屏来源文档以这两行共同构成唯一的 modal 根，因此助手仍可输入，底层工作台仍会 inert。页头用同一个
“来源资料／收起来源资料”控件开合右栏；内联右栏不再重复显示标题或关闭盒，只有抽屉或全屏层保留图标关闭操作。
右栏上半区的五个来源行只选择并定位到相应的业务检查点，保留当前文档、结论选择、滚动位置和焦点；打开来源文档
仍是当前任务或时间线回执的显式动作。下半区把审计时间线压缩为每个来源一行、每个来源差异一行和一条标准化结果，
即“来源／差异／结果”三类业务检查点；它不承载 DDL、代码或来源材料详情。

页头不展示“本次范围与限制”或重复的审阅计数；来源类型标签必须准确区分已保存来源、演示编写资料与派生术语图。源码或 DDL 摘录显示的是摘录内行号，真实文件位置仍紧邻
材料展示，避免把局部行号误读为原文件行号。

来源材料本身不可编辑，但 Demo 允许两个精确绑定的“建议核对”项：数据库的
`jsh_depot_head` 名称，以及代码仓库的负库存说明。用户只能“保留当前结论”或“采用推荐修改”；后者原位只显示
可修改的名称或业务说明，并说明确认后会同步更新审阅事项、审阅结论与标准化文档。来源材料、SQL/DDL和业务位置保持不变，
这些完整性边界只存在于内部审计而不作为用户文案。未决定的建议核对项会隐藏“完成本来源审阅”；保留只留下决定记录，采用才创建
新的来源文档 revision。首版任务可使用更短的业务名称；一旦用户确认或微调了名称，审阅事项、审阅结论、标准化文档和结论内依据都必须
逐字保留该名称，不能为了隐藏括号或技术标识而再次改写。`projectSourceReviewRevision()` 只把已验证的正式 revision 文字覆盖回同一 Claim 的三种
可见投影，绝不改写冻结来源字节或 trace。

审阅结论采用 Claim 优先展示：中文结论与其全部来源依据处于同一条内容内，SQL／DDL 只在“查看来源依据”折叠区
出现。对象目录默认展开；数据库依据先显示可核对的字段结构表和“重点字段 N/M”，完整结构与带行号、语法样式的原始 DDL 是次级
展开内容。文档说明和业务目标只关联自身的快照/审阅说明，不会错误打开索引、外键或 DML 摘录。内部 ID、SHA、摘要、
内部枚举和原始 JSON 只保存于运行时审计，不进入用户界面。

人类阅读投影的标题和说明必须先表达业务含义，再在必要时附带表名、字段或代码位置以便复核。不能把“状态机”、
“独立证据数量”、流程脚本或实现边界当作业务结论；冻结原文在用户主动展开依据时仍逐字保留，以保证可复核。

所有人类审阅投影还必须通过文字净化合同：禁止乱码、HTML 实体、TRACE 标记、摘要、内部证据类别和模板句；标题与正文不能重复，普通标题不超过 28 字、普通结论不超过 140 字。较长的物理表名和过程名不能挤进标题；标题保留简洁的业务名称，精确表名、过程名和原始 SQL／DDL 只在用户展开来源材料后显示。材料的保存范围只在来源级说明一次，不能作为重复的审阅结论。

运行前，`SourceCenter` 以 `RUN_CONFIGURATION` 出现：左侧是顺序固定的数据库、代码仓库、官方业务文档、ERP 管理制度、
术语图角色槽位；右侧默认“实例”、次级“连接器”。连接器家族先选具体技术再创建空白业务实例；只有已连接实例可通过拖拽、键盘或“添加到来源”绑定到兼容角色。待配置和连接失败实例只能配置。已连接但没有可用快照的实例可以绑定，但开始资料整理会失败关闭。选择仅保存 role-to-instance ID，开始运行后立即锁定；恢复演示清除该选择并恢复默认实例。运行后来源阅读仍来自固定绑定，不出现重新扫描。任何可见按钮只能发出命令、导航或展开资料区；每个页面和移动层最多一个主动作。

来源板的状态读取失败时，板面必须锁定：只允许恢复或重新读取，不能绑定、移除或替换实例。历史来源文档也是只读对象；控制器命令层而非仅页面按钮负责拒绝它的完成审阅、剧本修改与差异写入命令。来源审阅不提供重复的数字筛选或统计胶囊：待处理事项、资料缺口和已完成决定固定显示在“审阅事项”；核心结论和对象目录固定显示在“审阅结论”。

## 定版与保护

来源资料和三项治理决定完成后，作者依次“生成标准化结果”与“确认结果并定版”。完整 Markdown 会保留已确认结论、
资料缺口和无法确定项，并在每项缺口旁说明其不会进入 AI 建模。结果页同时展示可用于建模的结论数、已排除的缺口数和
“正式模型本次未改变”。定版重新校验来源 revision、决定、内容完整性、每条结论的来源／Markdown 定位，以及缺口没有
误入建模候选；已经登记的缺口或无法确定项本身不会阻止定版。作者、定版时间和输入 revision 进入审计记录；新运行不展示
独立审核、审批意见或审核人，历史审核记录仅为兼容读取。

定版后由“前往 AI 建模”交接完整标准化文档及其 `ModelingEligibility` 投影。AI 建模只编译 `ELIGIBLE` 结论；
`EXCLUDED_GAP` 与 `EXCLUDED_UNCERTAIN` 仍在交接文档的资料缺口区可读，但不会生成实体、关系、规则或指标候选。
时间线中的已读取来源、已生成／已审阅文档、已保存决定、已生成结果、已定版结果和已交接内容都保持可点击：当前步骤用于
继续工作，历史步骤以只读方式打开精确版本或决定，不覆盖既有审计记录。右侧流程面板默认跟随最新业务检查点；用户手动查看
历史后不抢走滚动位置，只有出现新的检查点时才显示“有新进度 · 回到当前步骤”。在作者定版前的`READY_FOR_OUTPUT`阶段，作者可从
某条已保存决定重新处理该差异；系统追加`CONFLICT_DECISION_REPLACED`事件和新的决定 Artifact，原决定继续保留在时间线中。
如果已经生成过结果，系统还会追加`DELIVERABLE_SUPERSEDED`，把上一份结果保留为只读历史、清空当前结果并提示重新生成；新决定
只会进入重新生成后的下一份结果。定版或交接后，历史决定只读。

这一过程不修改管伊佳 V1、Catalog、黄金摘要、对象计数或零售流程。多标签可访问，但并发写正确性仍由现有 CAS
尽力保护，不在本故事验收范围。
